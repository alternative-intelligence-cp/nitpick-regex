# 0.0.4 — `src/core/` — DONE (2026-09-06)

> **Scope:** `Vec<T>`, `Bytes`, `ByteSet`, `SparseSet` and `limits.npk` — the
> four storage primitives RX-006 decided to own rather than import, plus the
> one file every named bound lives in.

## 1. Decisions taken at planning

- **P-20 — `Vec<T>`'s block is `wild`, its lifetime its owner's scope.** The
  alternative — a managed `buffer` reinterpreted per element — needs a `=>!`
  per access, which is the unchecked reinterpretation the compiler's 1.4.2
  found five latent instances of. One `=>!`, in one file, checked once, is the
  shape that survives. **Every `Vec` has a `vec_free` and every scope that made
  one calls it**, or `exit 0` traps under D-151.
  **That enforcement covers the BLOCK and stops there.** D-151 counts `wild`
  blocks, D-188 counts live drivers, and neither sees a managed body, so
  `vec_free` on a `Vec` whose elements own heap storage releases the block and
  orphans the elements at exit 0 (RX-110). `vec_free`, `vec_clear` and
  `vec_truncate` each carry the obligation to drop what they discard, and the
  test for it is a memory cap rather than an exit code.
- **P-21 — `Bytes` is the only allocating string builder in the library.**
  `string_concat` allocates per call, and a replacement over a large haystack
  is thousands of small pieces: the compiler measured exactly this shape as
  quadratic in `npkg`'s first full run, seventeen minutes of fifty-six spent in
  the kernel. Nothing in `nregex` builds output with `string_concat` in a loop.
- **P-22 — `SparseSet` is the one with a real invariant, and it gets a property
  test rather than unit cases.** `dense[sparse[k]] == k` for every member, and
  membership is `sparse[k] < count && dense[sparse[k]] == k`. The
  uninitialised-`sparse` trick — never clearing the sparse array, because the
  dense check catches garbage — is what makes `clear` O(1), and it is the whole
  reason the Pike VM is linear per byte rather than per byte times program
  size. **Probe 08 says whether the language permits it**; if definite-assignment
  analysis refuses reading uninitialised storage, `sparse` is zeroed at
  allocation and `clear` stays O(1) anyway because only `count` is reset.
- **P-23 — every accessor's obligation is written now**, in the syntax it will
  take, as a comment, with a property test standing in
  (`VERIFICATION.md` P-1). Deleting a comment marker in cycle 1.5 is a smaller
  change than inventing the clause then, and probe 13 has confirmed the syntax
  is inert rather than silently parsed as something else.

## 3. `Vec<T>`

| Function | Contract (written as a comment now) |
|---|---|
| `vec_init<T>(cap)` | `ensures result.count == 0 && result.cap >= 1` |
| `vec_reserve<T>(v, need)` | `ensures v.cap >= v.count + need` |
| `vec_push<T>(v, move T:x)` | `ensures v.count == old(v.count) + 1` |
| `vec_pop<T>(v)` | `requires v.count > 0` |
| `vec_at<T>(v, i)` | `requires i >= 0 && i < v.count` |
| `vec_set<T>(v, i, move T:x)` | `requires i >= 0 && i < v.count` |
| `vec_truncate<T>(v, n)` | `ensures v.count == min(n, old(v.count))` |
| `vec_insert<T>(v, i, move T:x)` | `requires i >= 0 && i <= v.count` |
| `vec_remove<T>(v, i)` | `requires i >= 0 && i < v.count` |
| `vec_swap_remove<T>(v, i)` | `requires i >= 0 && i < v.count` |
| `vec_clear<T>(v)` | `ensures v.count == 0` |
| `vec_free<T>(v)` | `ensures v.cap == 0 && v.items == NULL` |

**Rule:** `vec_at` returns by value and is therefore for scalar `T` only — for
an owning `T` a copy is refused (TYPE-046), and the family reads through
`v.items[i]` at the site that knows the element's shape. This is the compiler's
own `List<T>` note and the reason there is no generic `list_at` there either.

## 4. `SparseSet`

```nitpick
pub struct:SparseSet = { Vec<int32>:dense; Vec<int32>:sparse; int64:count; };
```

| Function | Contract |
|---|---|
| `sset_init(cap)` | `ensures result.count == 0` |
| `sset_insert(s, k)` | `requires k >= 0 && k < s.sparse.count` |
| `sset_contains(s, k)` | `requires k >= 0 && k < s.sparse.count` |
| `sset_at(s, i)` | `requires i >= 0 && i < s.count` |
| `sset_clear(s)` | `ensures s.count == 0` — **O(1)** |

**The property test**, over ten thousand random operation sequences: after
every operation, `sset_contains(s, k)` agrees with a reference `Vec<bool>`, and
for every `i < count`, `sparse[dense[i]] == i`.
