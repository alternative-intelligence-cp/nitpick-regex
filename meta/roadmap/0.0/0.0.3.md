# 0.0.3 — the harness, part 2 — PLANNED

> **Scope:** the remaining stages, the self-check that proves the harness can
> fail, and the tree checks that diff the library against the documents
> describing it. **The self-check is the load-bearing half**: a suite that only
> ever agrees with what it is handed reports green while checking nothing.

## 1. Decisions taken at planning

- **P-15 — the exact-code rule from the start** (D-237, `BUILD.md` B-7). On the
  error channel the SET of codes a rejection test reports must EQUAL the set
  its expectations name. The compiler ran the weaker subset rule for six cycles
  and found, when it tightened, that 17 of 131 files were reporting something
  nobody had asserted. Starting strict costs nothing; loosening later is
  impossible.
- **P-16 — the tree checks run on every full invocation**, including the ones
  that currently have nothing to check. `check_error_kinds_tested` over an
  empty enum is the right answer and is what makes the check exist on the day
  the first kind is written.
- **P-17 — `--only` prints, twice, that a filtered run concludes nothing**, and
  nothing is committed on the strength of one. The compiler's phrasing, adopted
  whole, for the same reason.
- **P-18 — two self-check cases are written now and marked PENDING.** The
  corpus and oracle cases cannot run until 0.5. Writing them now means the day
  the stage lands the case already exists; marking them pending means they
  print as pending rather than passing, which is the difference between a
  placeholder and a lie.

## 2. The stages added

| Stage | Tool | Passes when |
|---|---|---|
| `parse` | the compiler's `tools/parse_check` | every `.npk` in the tree accepted with no diagnostic, each once |
| `accept` | the compiler's `tools/check` | accepted in silence |
| `check` | the compiler's `tools/check` | refused with **exactly** the expected codes |

The tools come from the compiler's tree, built once per run from the pinned
checkout.

## 3. The self-check — the seven cases

`harness/selfcheck.py` constructs each case, runs the harness against it, and
requires a **failure**:

1. a `program` case whose `expect-exit` is wrong by one
2. a `check` case expecting a code the compiler does not report
3. a `check` case reporting a code no expectation names — the D-237 rule
4. a `parse` case that does not parse
5. a generated table differing from the generator's output by one line
   *(pending until 0.3)*
6. a corpus fixture whose expected offsets are off by one *(pending until 0.5)*
7. **a corpus fixture that passes under one engine and fails under another**
   *(pending until 0.8)* — the case proving RX-041 is doing work, and the most
   important one in the list

**Rule:** the self-check runs **first** in every full invocation, and a pending
case prints as pending rather than passing.

**Rule P-19 — `check_error_budget` is the one a consumer depends on.** "Importing
`nregex` costs your `failsafe` exactly one arm" is a promise no compiler will
check for us, and this is what keeps it true.
