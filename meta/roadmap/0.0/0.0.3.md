# 0.0.3 — the harness, part 2 — DONE (2026-09-04)

> **Scope:** the remaining stages, the self-check that proves the harness can
> fail, and the tree checks that diff the library against the documents
> describing it. **The self-check is the load-bearing half**: a suite that only
> ever agrees with what it is handed reports green while checking nothing.

## 1. Decisions taken at planning

- **P-15 — the exact-code rule from the start** (D-237, `BUILD.md` B-7). On the
  error channel the SET of codes a rejection test reports must EQUAL the set
  its expectations name. The compiler ran the weaker subset rule for six cycles
  and found, when it tightened, that 17 of 131 files were reporting something
  nobody had asserted. Starting strict costs nothing; loosening later is
  impossible.
- **P-16 — the tree checks run on every full invocation**, including the ones
  that currently have nothing to check. `check_error_kinds_tested` over an
  empty enum is the right answer and is what makes the check exist on the day
  the first kind is written.
- **P-17 — `--only` prints, twice, that a filtered run concludes nothing**, and
  nothing is committed on the strength of one. The compiler's phrasing, adopted
  whole, for the same reason.
- **P-18 — two self-check cases are written now and marked PENDING.** The
  corpus and oracle cases cannot run until 0.5. Writing them now means the day
  the stage lands the case already exists; marking them pending means they
  print as pending rather than passing, which is the difference between a
  placeholder and a lie.

   *(pending until 0.3)*
6. a corpus fixture whose expected offsets are off by one *(pending until 0.5)*
7. **a corpus fixture that passes under one engine and fails under another**
   *(pending until 0.8)* — the case proving RX-041 is doing work, and the most
   important one in the list
8. **a program that makes a syscall** — `harness/selfcheck/syscall_consumer.npk`,
   committed. Must fail `B-2a` by naming the function and `npk_sys6` (RX-120)
9. **a program that needs a floor symbol the baseline does not have** —
   `harness/selfcheck/new_symbol_consumer.npk`, committed. Must fail `B-2` by
   naming `npk_ralloc` (RX-116)
10. **a non-deterministic emission** — the `repro` check must report the byte
   offset (B-4). 0.0.2 demonstrated it by substituting the emitter; 0.0.3 owns
   whether that stays a substitution or becomes a fixture.
   **DECIDED 2026-09-04: NEITHER, and the case tests the INSTRUMENT directly.**
   A substituted emitter tests a fake `npkc` and so proves nothing about the
   real one. A fixture *cannot exist*: a file whose IR differs between two
   builds of the same tree is precisely what D-078 and D-236 say the compiler
   never produces, so committing one would mean committing a compiler defect as
   a test input — and the day it was fixed the case would go green by turning
   into its opposite. So the case feeds `repro`'s comparison two byte sequences
   differing at a known offset and requires it to report **that** offset. The
   two-working-directory machinery around it is exercised for real on every full
   run by the `repro` build step, which has already been seen to fail (0.0.2 §6
   D4).

**Rule:** the self-check runs **first** in every full invocation, and a pending
case prints as pending rather than passing.

## 2. The re-pin: three probes owed, and what they actually establish

The dispatch owed three measurements, on the stated ground that *"`Vec<T>` did
not own until D-247"*. **All three re-ran clean** — `npkc` 0, `llc` 0, `ld.lld`
0, binary 0 at −O0 **and** through `opt -O2`; no `WildLeak` trap (96), no
double-free trap.

| Probe | Shape | −O0 | −O2 | peak RSS |
|---|---|---|---|---|
| `probe03_generic_move.npk` | `free_owning`: every element moved out, then `vec_free` | 0 | 0 | — |
| `probe04_inherent_generic_impl.npk`:89 | `pass self.count` over `Vec<T>` **by value** — DEF-8's shape exactly | 0 | 0 | — |
| `probe08_sparse_set.npk`:117 | `sset_has(SparseSet:s, …)` — the nested-container sibling | 0 | 0 | 768 KiB |

**And the premise was false, which changes what the greens mean — RX-126.**
D-247 makes the compiler-known **`List<T>`** owning. Its recognition is keyed, in
`src/frontend/type_layout.npk`'s `decl_is_list` read at the pin, on **all** of: a
file in the program whose **basename is `list`**; the declaration's home scope
being that module's; the struct being named **`List`**; and its fields being
exactly `items` (a pointer), `count`, `cap`, in that order, and no others. The
predicate's own comment: *"A same-named struct anywhere else (a test's own
`List`) is an ordinary struct."*

**This repository has no `list.npk` and its container is `Vec`.** So `Vec<T>` is
an ordinary struct holding a `wild T->` block, exactly as at `950bb1d`. The three
probes are therefore **not** evidence that DEF-8's fix is right for this shape —
they are evidence that the shape is **outside DEF-8's scope**, because DEF-8 is
about the drop flag of an *owning* local and `Vec<T>` does not drop. Recording
them as "DEF-8 verified here" would have been the fifth unfalsifiable green in
this ecosystem.

Consequences, each stated so a later cycle does not re-derive them: nothing about
`Vec<T>`'s design needs revisiting at 0.0.4; `SAFETY.md` §8b and `0.0.4.md` P-20
stand unchanged; **and the 125 MiB managed-body gap is not closed** — D-247 would
have closed it for a `List<string>`, not for a `Vec<OwningGroup>` — so RX-110 and
RX-123 both stand at full strength.

`probe01` (POD) and `probe07` (slice parameter) were checked at dispatch and are
clear; `probe03`/`probe06` `move` an *owning* element, the legitimate case.

## 3. The re-pin: two probes the harness itself reported RED

**Nobody went looking for these.** The first full run of the new harness came
back `60/63`, with two failures neither the plan nor the dispatch anticipated.

```
FAIL  probe-refused/…/probe02b_derive_eq_refused.npk: expected NITPICK-TYPE-034,
      but it compiled cleanly (exit 0)
FAIL  probe/…/probe02c_derive_ord_tag_only.npk: exited 20, expected 0
```

**Exit 20 was reserved for this.** `probe02c`'s header, written at cycle 0.0.0:

> *If this line ever exits 20, O-N10 HAS LANDED: `cmp` now reads payloads … Do
> not "fix" the probe — read the header and delete the nesting.*

**Workbench registry O-N10 is DISCHARGED, both halves, on this repository's own
measurement — RX-125.** Thirteen properties were measured before anything was
written:

| | `950bb1d` | `94874ce` |
|---|---|---|
| `#[derive(Eq)]` on a payload enum | `NITPICK-TYPE-034` at `<derived-1>:2:82` | accepted, correct |
| `#[derive(Ord)]`'s `cmp` | payload ignored; `Repeat(2,5).cmp(Repeat(9,9))` = `Equal` | lexicographic over every field |

**Two of the thirteen are this repository's own and no `nitpick-time` test can
make them.** Its enum carries one payload field per variant, so a fix that read
only the FIRST field would have passed everything there. Here
`Repeat(2,5) < Repeat(2,9)` — the second field breaks the tie — and `Repeat(2,5)`
is distinguished from `Repeat(9,5)` as well as from `Repeat(9,9)`.

**A caller-visible residue:** `.eq()` returns `Result<bool>` and `.cmp()` returns
`Result<Ordering>`; `if (a.eq(b))` is `NITPICK-TYPE-007`, *"there is no
truthiness in Nitpick"*. So `probe02_payload_enum.npk`'s hand-written `hir_eq` is
**not** simply deleted — a derive threads an error channel and `SAFETY.md` §4's
budget is charged by channels. That is a **cycle 0.2** decision with the cost on
the table. `HIR.md` H-2 is untouched: its primary reason is TYPE-046, which never
involved O-N10; only `probe02b`'s *supporting* argument expired, and RX-125 marks
it expired rather than deleting it.

**Both files were renamed**, because `…_refused` and `…_tag_only` had become
false claims. §6 is the redirect table; cycle 0.0.0's verdict table and
`tests/probe/TRANSCRIPT.txt` are artifacts of a pin and were **not** edited.

## 7. `check_no_syscalls`: the instrument measured at BOTH optimisation levels

RX-120 stands, and it now stands at −O2 as well, which had not been measured.

| | −O0 | −O2 |
|---|---|---|
| baseline — `npk_sys6` call **sites** | 2 | **5** |
| syscaller — `npk_sys6` call **sites** | 3 | **6** |
| baseline / syscaller — **undefined symbols** | 29 / 29 | 28 / 28 |
| symbol-set difference | **EMPTY** | **EMPTY** |
| baseline — functions with a `npk_sys6` **edge** | 2 | 5 |
| syscaller — functions with a `npk_sys6` **edge** | 3 (incl. `main`) | 6 (incl. `main`) |
| **edge-set difference** | **`main`** | **`main`** |

Two things follow, and only the first was predicted. **The site count goes 2/3 to
5/6 under `opt -O2` because inlining duplicates the floor's own sites** —
`std_err`, `std_in` and `std_out` join `std_dup` and `ByteReader.seek`. **And the
difference is unaffected**: inlining adds the same three functions to *both*
sets, so the edge-set difference is exactly `main` at either level. The
instrument does not depend on the optimisation level, which was worth knowing
because it was not obvious that `main`'s own call would survive `-O2` unmerged.

**Which leg the harness takes:** the IR call-edge scan runs on the **−O0** IR
only (`build.emit_and_link`); the optimised leg re-runs the *symbol* scan in the
minting direction alone. That is sound — `opt` can duplicate a `sys()` call but
cannot invent one — and the table above is what lets that be said rather than
assumed.

## 8. Findings

1. **A correction stops where its author's attention stopped, twice in one
   subcycle.** RX-110 fixed six statements of the leak gate and missed two, both
   in **acceptance checklists**, because neither cited `D-151` and the sweep was
   `git grep 'D-151'` (**RX-123**). Rule B-4a struck the `accept` stage for
   depending on a compiler-repository tool and left the `parse` row, two rows
   above it in the same table, depending on another one (**RX-124**). *When a
   rule strikes one row of a table, read the other rows for the same reason.*
2. **A generating command is only as wide as its pattern.** The two missed sites
   were found by grepping the CLAIM's words, not its citation, and a third
   phrasing (the bare word `leak`) surfaced two further candidates that were then
   judged **correct** and left alone — `probe14`'s POD `Vec<Inst>` line, where
   `exit 0` genuinely does cover the whole obligation.
3. **A probe that asserts what the compiler DOES, not what it should, reports the
   fix on the day it arrives.** `probe02c` was green through the defective period
   by design and went red the day O-N10 landed. A probe asserting the correct
   answer would have been green on both days and told nobody anything. This is
   the strongest evidence in the repository for the convention.
4. **SIX of this library's eight `src/` files reached no suite at all** until
   the `parse` stage existed. `src/lib.npk` `pub use`s one name, from `api`, so
   `core`, `compile`, `engine`, `hir`, `syntax` and `unicode` were last compiled
   at cycle 0.0.1 and nothing re-checked them for three subcycles. The green runs
   in between were honest about what they *did* cover and silent about this,
   which is why a check reports its DENOMINATOR here and not only its verdict.

   **And the sweep does not close that gap fully, which is stated rather than
   enjoyed.** `npkc` exit 0 is not well-formedness (O-N11) and this library is
   the standing example — all eight `src/` files compile at exit 0 and all eight
   are refused by `llc` (RX-115, B-0). So the six are now checked **as far as the
   frontend** and no further; nothing assembles or links them, because there is
   no library object to make one from. O-N14 is what would change it. The gap
   closed was "checked by nothing"; the gap remaining is "checked only to the
   frontend", and those are different sizes.
5. **The plan's own counts were wrong twice**, and both were caught by building
   it: "seven live cases … and case 4 live" is eight, and "the five live tree
   checks" is four, because one of §4's five is a **build step** that landed at
   0.0.2 and would have been a second copy of itself here.
