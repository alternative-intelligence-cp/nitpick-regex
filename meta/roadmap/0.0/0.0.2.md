# 0.0.2 — the harness, part 1 — DONE (2026-09-04)

> **Scope:** `harness/run.py` builds the library and judges a `program`-stage
> test by its exit code, at -O0 and again under `opt -O2`, with the toolchain
> pinned and two symbol scans as build steps. This is RX-004's runner and it
> retires into `npkg` when O-G3 closes.

## 1. Decisions taken at planning

- **P-10 — the harness reads `nitpick.toml` and never hardcodes a path.**
  Entry, output, opt-level, the four flag lists and the `[[test]]` table all
  come from the manifest, for the compiler's own D-204 reason: a stated flag
  nothing consumes is the next stale document. The one thing it takes from the
  environment is `NPKC`, the compiler to test with.
- **P-11 — the undefined-symbol scan is a build step and fails the build**
  (`BUILD.md` B-2), not a test that can be skipped. It reads the object's ELF64
  symbol table directly rather than spawning `llvm-readelf`: a fourth tool
  outside the pin, whose text output nothing checks, is a poor foundation for a
  rule that is law. Python's `struct` module reads an ELF symbol table in about
  forty lines.
  > **HELD, and both halves earned their place.** `harness/elf.py` is 96 lines
  > and agrees with `llvm-nm --undefined-only` symbol for symbol — 29 against
  > 29 — and reproduces `TRANSCRIPT.txt` §D3's 201 defined symbols in
  > `npkrt.o`. It is a build step: a failure stops the run before any suite.
- **P-12 — `check_no_syscalls` is a SECOND scan, and it is `nregex`-specific.**
  The first scan asks "is every undefined symbol in the runtime's allowlist".
  The second asks "is every undefined symbol in **this** committed list" — the
  allocator, `memcpy`/`memset`, and the string primitives. RX-008 says the
  library makes no syscall and is target-independent; this is what keeps that
  true, and a convenience that reads a file would fail here rather than in
  review a year later.
  > **SUPERSEDED TWICE, and the second time is this subcycle's main finding.**
  > RX-116 had already replaced *"the runtime's allowlist"* and *"this committed
  > list"* with a difference against an empty baseline program, because a
  > program containing no library code at all fails an absolute list. What 0.0.2
  > found is that **the difference cannot see a syscall either** — measured, §5.
  > The second scan survives, but it is an **IR call-edge** scan and not a second
  > symbol list (RX-120), and both layers apply to programs that reach `src/`
  > (RX-121).
- **P-13 — `opt -O2` is a check leg on every program, always**
  (`BUILD.md` B-3). The compiler's own version of this instrument found a real
  defect on its first run that had passed for six cycles. A missing `opt` fails
  loudly rather than skipping.
- **P-14 — one build of the library per run, reused by every program.** The
  library compiles once to an object; each test program compiles and links
  against it. A per-test rebuild is the difference between a two-minute suite
  and a forty-minute one, and it is worth getting right before there are
  hundreds of corpus programs.
  > **NOT ACHIEVABLE AT THIS PIN, and deliberately not worked around.**
  > **There is no library object** (`BUILD.md` B-0, RX-115): every file in
  > `src/` compiles at `npkc` exit 0 and every one is refused by `llc`, because
  > a library file cannot define `@npk_failsafe` and `npkc` never declares it.
  > So each program root compiles the whole graph it reaches. It costs nothing
  > measurable today — 24 units in **22.7 s**, and only one of them imports
  > `src/` at all — and the answer is not to reshape anything but to wait:
  > provisional workbench **O-N14** is accepted into the compiler's 1.5.1b step
  > 3c, which additionally adds an `object` stage to both runners. The day it
  > lands, P-14's shape becomes possible and `harness/build.py` is the file that
  > changes. Nothing else in this repository is arranged around the gap.

## 2. The pipeline

As planned:

```
manifest ─► module graph ─► npkc  ─► nregex.ll
                                  ├─► opt -O2 ─► nregex.opt.ll     (check leg)
                                  └─► llc      ─► nregex.o
                                          ├─► ELF undefined-symbol scan (allowlist)
                                          └─► check_no_syscalls (committed list)
per program: npkc ─► p.ll ─► llc ─► p.o ─► scan ─► ld.lld(p.o, nregex.o, npkrt.o) ─► run
```

**As built**, and the three differences are B-0, RX-116 and RX-120 rather than
taste — `nregex.o` does not exist, the allowlist cannot be written, and the
symbol scan alone cannot see a syscall:

```
build steps, once per run, a failure in any one stopping the suites:
  baseline    harness/baseline/baseline.npk ─► npkc ─► llc ─► ld.lld ─► run(0)
                 └─► SYMBOLS.txt (29)  and  EDGES.txt (237)   diffed against committed
  libcheck    npkc [build] entry — a parse-and-resolve check, and NOT evidence
              that the library builds (B-0)
  repro       the tree copied to two roots, the same relative command in each,
              the .ll compared byte for byte (B-4)

per program root, and the library is reached only this way:
  npkc ─► p.ll ─► IR call-edge scan (B-2a) ─► llc ─► p.o
                                            ─► ELF undefined-symbol scan (B-2)
                                            ─► ld.lld(p.o, npkrt.o) ─► run, exit judged
  and again: p.ll ─► opt -O2 ─► llc -O2 ─► scan ─► ld.lld ─► run, SAME exit (B-3)
```

## 3. Steps

1. **`harness/manifest.py`** — a minimal TOML reader (the manifest is small and
   the subset used here is a dozen lines), the schema check, and a loud refusal
   naming any key the schema lacks.
2. **`harness/toolchain.py`** — asks `llc --version`, `opt --version` and
   `ld.lld --version` and refuses a mismatch against `[toolchain] llvm`. Asks
   the tools, not `llvm-config`, which is a `-dev` package the build does not
   need.
3. **`harness/elf.py`** — the ELF64 symbol-table reader, the allowlist
   derivation from `runtime/npkrt.ll`, and the committed `nregex` symbol list.
4. **`harness/build.py`** — the pipeline above, every argv built from the
   manifest's flag lists.
5. **`harness/stages.py`** — the `program` stage: read `// expect-exit:`,
   `// stress: N` and `// argv:` from the file; run; compare; repeat against the
   optimised object.
6. **`harness/run.py`** — the driver: stage order, per-unit verdict lines,
   `--only`, `--verdicts PATH`, and a summary stating the counts.
7. **The `repro` check** — build twice from two working directories, compare
   the emitted `.ll` byte for byte, fail loudly on a difference.
   Reproducibility is a tested property or it is not a property.
8. **One real program** — probe 01 from 0.0.0, run as a `program`-stage entry,
   green under both legs.

## 6. What the syscall scan actually catches, and how that was found

**The instrument 0.0.2 was planned around cannot detect a syscall.** This is the
subcycle's finding, it is measured rather than argued, and it was found by
trying to satisfy the acceptance item that names it.

RX-116 replaced the unrunnable allowlist with a difference: an `nregex` program
object's undefined-symbol set must equal an empty baseline program's. Two
four-line programs at the pin, differing **only** by a `sys(39i64)` call in
`main`:

```
$ $NPKC $SP/syscheck/baseline.npk  -o $SP/syscheck/baseline.ll     -> exit 0
$ $NPKC $SP/syscheck/syscaller.npk -o $SP/syscheck/syscaller.ll    -> exit 0
$ llc -O0 -filetype=obj -relocation-model=static … baseline.ll  -o baseline.o   -> exit 0
$ llc -O0 -filetype=obj -relocation-model=static … syscaller.ll -o syscaller.o  -> exit 0

    baseline   undefined: 29     `call i64 @npk_sys6` sites: 2
    syscaller  undefined: 29     `call i64 @npk_sys6` sites: 3

$ diff baseline.syms syscaller.syms
  (no output)                                                      -> exit 0
```

**Symmetric difference empty.** `npk_sys6` is in every object already: the two
baseline sites are `npk.resume.prelude.ByteReader.seek` and
`npk.prelude.std_dup`, both emitted into every translation unit. The
syscaller's third site is in `@main`. So the specified check reports a clean run
over a program that has just made a syscall, and the acceptance item would have
been ticked by an instrument that cannot do the thing the item names.

**A first attempt at the fix was wrong in a way worth recording**, because it is
the same shape as everything else here: counting `@npk_sys6` sites. Measured,
the count is 2 against 3 at −O0 and **5 against 6 after `opt -O2`** — inlining
duplicates the floor's own sites — so the number depends on the optimiser, and
it names no function. The scan is on the emission, and it is an edge and not a
count.

**And the first version of the edge scan failed all sixteen probes**, correctly
each time, which is what produced RX-120's three refinements and RX-121:
`llvm.*` intrinsics are not the floor; `npk.drop.365` and `npk.drop.367` are the
same glue renumbered; and a permit list has to swallow `npk_trap`, the `defer`
chain, the allocator and `npk_string_concat` — most of what any program calls —
where a **deny** list of the seven kernel-and-descriptor symbols does not.

### What was found, in the order it was found

1. **The undefined-symbol difference cannot see a syscall.** §6. This is the
   subcycle's finding and it was found by trying to satisfy the acceptance item
   that names it, rather than by reading anything. RX-120.
2. **A count of call sites is not a usable instrument**, because `opt -O2`
   inlining takes it from 2/3 to 5/6. Measured before it was adopted, not after.
3. **The first edge scan failed all sixteen probes, correctly**, and produced
   three refinements — `llvm.*` is not the floor; generated glue is numbered and
   the number moves; a deny list is smaller and truer than a permit list — and
   then RX-121, which is the scoping the rule already had in its own words and
   the implementation had not.
4. **A latent bug in `reaches_src`**: it compared a possibly-relative path
   against an absolute prefix and answered **no** for everything, silently. A
   silent no means the scans never run. Caught by running it on four known files
   both ways.
5. **`opt -O2` legitimately removes an undefined symbol**, so the optimised
   leg's scan is one-directional. `TRANSCRIPT.txt` §D had measured 29 → 28 at
   0.0.1 and the rule had not been written down.
6. **A false claim, caught before it was committed.** `expect.py`'s docstring
   asserted that `npkg` runs a `stress: 0` test zero times and reports it green.
   `run_binary` opens `if (runs < 1i64) { runs = 1i64; }`. The refusal stands;
   the reason was wrong and is corrected in place, in RX-122 as well as in the
   file. **The claim was written from the shape of the loop and not from the
   lines above it** — the same one-call-too-early reading that produced 0.0.1's
   `pass 2i32` error, and it was caught only because the source was opened to
   quote it.
