**Why the zero-length array works — read in the compiler at `c3bdae2`, then
measured.** `type_drops_recorded` answers an array by its ELEMENT, whatever the
length, and `struct_layout_bound` marks a struct owning when any field is
(D-183); `require_move_if_owning` then makes a copy of an owning place
`NITPICK-TYPE-046`. The array's size is its element's times zero. `[]` is D-139's
zero array, and the checker's own comment says *"`int32[0]:a = [];` is fine"*.
The generated drop is a loop that exits before its first element (read in the
emitted IR: `icmp uge i64 %i, 0`), so it frees nothing: **the block stays `wild`,
freed only by `vec_free`**, and a `Vec` never freed still traps `WildLeak` at
`exit 0` (96, measured under every marker above). The `int64[0]` control proves
the mechanism is the element's ownership and not the zero length.

### 1.4 The sixth shape is a LOAN, and what a loan still reaches is a compiler defect

**`vec_alias_param_free` compiles under every marker in §1.2, and still reads the
free poison (0).** Not a gap in the marker: a by-value parameter is not a copy.
The compiler's D-065 — *"Passing an owning value to a function borrows it"* — and
D-183 — *"an ordinary parameter is a value the callee may read and may not
keep"*; `type_members.npk` requires `move` only of a `move` parameter (*"ONLY A
`move` PARAMETER TAKES OWNERSHIP … An ordinary one is a loan"*), and
`refuse_move_of_borrowed` refuses `move(p)` of a lent `p` (`TYPE-047`). **What
it does not refuse is a WRITE through the loan**: `@p` is allowed, and so is
every assignment into `p` or its fields.

Measured, each with the marker and without it (the same results both ways):

| unit (new unless noted) | shape | result |
|---|---|---|
| `vec_alias_param_free` (exists) | callee `vec_free(@v)` on its lent `Vec` | 0: the caller reads the poison |
| `vec_alias_param_grow` | callee pushes through `@v` until `ralloc` moves the block | **95**: the caller's own `vec_free` meets the block `ralloc` released — the guard sees `cap == 1` |
| `sparseset_alias_param_free` | callee `sset_free(@s)` on its lent `SparseSet` | 0: the caller reads member 3 ABSENT while `sset_len` says 1 — RX-160's worst row, through a loan |
| `bytes_alias_param_grow` | callee pushes through `@b` on a lent `Bytes` — a type move-only ALL ALONG | **95**: `bytes_reserve`'s `b.buf = move(bigger)` drops the CALLER's body, and the caller's own drop frees it again |

**The pure form, no library code, no `wild`, no pointer cast** — this is what
§6.1 raises:

```nitpick
struct:Box = { string:s; };
func:overwrite = NIL(Box:b) never fails {
    b.s = string_concat("xyzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzz", "w");
    pass NIL;
};
// main: Box:b = Box{ s: string_concat("abb…b", "c") }; drop overwrite(b);
//       then b.s's first byte:  0xAA, the free poison          -> exit 70
//       (returned normally instead of exiting: the drop frees it again -> 95)
```

Controls, the same day: the same write on a `move Box:b` parameter, called with
`move(b)`, runs 0; the same write on a local runs 0 and reads the new value; a
whole-binding assignment to a lent `string` parameter (`s = …`) does NOT drop the
caller's value — so the compiler knows the parameter is lent, and forgets it for
a FIELD. **The mechanism, read at `c3bdae2`:** `ir_stmt.npk`'s assignment
lowering drops a field target's old value unconditionally — D-186, whose comment
reads *"the field belongs to the struct, and the struct's owner is exactly who is
overwriting it"*. For a lent parameter, the overwriter is not the owner.

**What this means for the plan:** no type change in this library can refuse a
loan, and working around the defect in `src/` is forbidden (W-11). So this
subcycle **pins** the loan — the existing unit, three more, and probe 17 — each
saying what to do when it reddens, **raises** the defect by path, and states
the residue where a reader meets it (S-23b's last two rows). Every function in
`src/core/` that changes a container already takes it by pointer; nothing in
`src/` writes through a by-value container.

*(Amended at execution, 2026-09-25, by the dispatch: the defect was numbered
before this subcycle ran — it is the workbench registry's **O-N21**, sent to the
compiler seat at 19:55 — so the texts this plan's tools write say "raised as

### 1.5 `vec_get`'s signature does NOT change — the audit's expectation, measured false

The fourth audit (BL-8) and RX-160 expected move-only to change `vec_get` (which
takes `Vec<T>:v` by value) and *"every by-value read in `src/core/`"*. Measured:
with the marker, all of `src/` and every unit compile unchanged — a by-value
parameter is a loan, and a loan of an owner needs no `move`. **`vec_get` keeps its
signature (PD-9)**, for three reasons: a loan is the language's read-only
parameter convention (D-183's `string_eq(a, b)` case); it lets a consumer read a
sealed field, `vec_get(s.sparse, k)`, without taking the address D-313 counts as
a write; and nothing in `vec_get` writes through `v`.

*Declined:* **`vec_get(Vec<T>->:v, …)`** — a consumer's `vec_get(@s.sparse, k)`
is then `NITPICK-TYPE-079`, so `SparseSet` would need new accessors, and it closes
nothing: a consumer's own by-value parameter is still a loan. **Consuming verbs**
(`vec_free(move Vec<T>:v)`, growth paths that take and return the `Vec`) would
make a callee's free and growth through a loan `TYPE-047` — reshaping the API
around a compiler defect, at a copy in and out of every call in the Pike VM's
inner loop, and not reaching the field drop, which needs no library verb.

## 3. What will bite

- **A `release` in a name.** It is a memory-ordering keyword: a function
  DECLARED `release` compiles, and every CALL of it is `PARSE-002` *"expected an
  expression"* at the name. `acquire`, `relaxed`, `acq_rel`, `seq_cst` too.
- **The five moves need `git mv` BEFORE `d4d_tests.py`**, which rewrites them in
  `tests/rejection/` and STOPS if they are not there. **And git will not call them
  renames**: the new header outweighs the unchanged body, so `git status` after
  `add` shows `D` and `A`, not `R`. That is expected (step 8), not a lost file.
- **A rejection fixture's position moves with its header.** `d4d_tests.py` edits
  `bytes_len_write.npk` and `bytes_copy.npk` without changing their line counts
  (it STOPS if a count changes), so 28:5 and 27:5 hold; the seven new positions
  are measured in step 4, never counted.
- **`--only` in a clone judges the clone.** The harness roots itself at its own
  file, so `$A/before/harness/run.py` judges `$A/before`. Never run the clone's
  harness against `$REPO` or the reverse.
- **A by-value `Vec` parameter compiles.** It is a loan, not a copy. Do not "fix"
  a loan unit by adding `move` — `move` of a lent parameter is `TYPE-047`, and the

### 6.1 A compiler defect: a callee's write through a LENT parameter frees the caller's value

*(Amended at execution, 2026-09-25: this defect is the workbench registry's
**O-N21** — §1.4's note and the execution record. The section below is the plan
as it was written, when the defect was still to be raised by path.)*

**Raise by path** (the worker skill §5 and `PLAYBOOK.md`: a worker cites a new
question by path, the orchestrator numbers it) — this section is the path until
`tests/probe/probe17_lent_field_drop.npk` lands, which is the committed form.
**Reproduction**, no library code, measured at `c3bdae2` at −O0 and through
`opt -O2`:

```text
struct:Box = { string:s; };
func:overwrite = NIL(Box:b) never fails {
    b.s = string_concat("xyzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzz", "w");
    pass NIL;
};
main:  Box:b = Box{ s: string_concat("abbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb", "c") };
       drop overwrite(b);
       uint8[]:bs = string_bytes(b.s);
       bs[0] == 0xAA  -> exit 70      the caller reads its own string's body, freed
returned normally from a function instead of exiting:  95  (the caller's drop frees it again)
through `@b` handed to a callee that writes `p.s = ...`:  95, the same
controls: the write on a `move Box:b` parameter: 0; on a local: 0, reads the new value;
          `s = ...` to a whole lent `string` parameter: the caller's value SURVIVES
```

**What it reaches in this library** (§1.4's table): a lent `Bytes` grown by its

an assignment into a place rooted at a lent parameter, and `@` of one — which
closes both faces; a fix that only stops the field drop would leave the `@p`
face, which is `wild` and invisible to drops. **What it blocks** (W-27): nothing
in `src/`, which changes containers only through pointers; any consumer — the
parser at cycle 0.1 first — that writes through a by-value container. **Not a
regression**: it is D-186's rule as written.
