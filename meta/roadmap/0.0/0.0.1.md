## 2. Decisions taken at planning

- **P-6 — one placeholder module per directory, and it parses.** An empty
  directory is invisible to the `parse` sweep, and the sweep is what stops the
  grammar being quietly made partial. Each placeholder is
  `src/<dir>/<dir>.npk` with `mod:<dir>;` and a header comment naming the
  specification section that will fill it and the cycle that does. They are
  replaced, not deleted.
- **P-7 — `src/lib.npk` re-exports deliberately, one line per public name.**
  `use` is not transitive (`MODULE_REFERENCE.md` §2.3), so the surface is a
  list a reviewer can read in one file. That is a feature and it is why the
  library has an umbrella at all. `API.md` §1 is the list it will grow into.
- **P-8 — the consumer test imports by relative path** (`BUILD.md` B-15) and
  carries a comment naming **O-G3** as the reason, so the day dependency roots
  work, the thing to change is greppable.
- **P-9 — CI pins the compiler by commit**, not by branch. The compiler is
  moving through cycle 1.5; a library whose CI tracks its `main` is a library
  whose CI breaks for reasons that are not its own. Bumping the pin is a
  deliberate commit that runs the full suite.

## Execution record

### 2026-09-03, stream 1, toolchain `950bb1d` (LLVM 20.1.2)

**What was done.** Eight files in `src/` — seven placeholders, one per layer of
`BUILD.md` §6's diagram, and the umbrella — plus `tests/conformance/import.npk`,
the manifest's first `[[test]]` entry, `.github/workflows/ci.yml`, a harness
stub, and a re-read of both guides. Every command is in
[`../../../tests/conformance/TRANSCRIPT.txt`](../../../tests/conformance/TRANSCRIPT.txt)
with its exit code, including six controls.

**The subcycle produced almost no code and five specification corrections.**
That is the right ratio for a skeleton: what a skeleton tests is whether the
documents describing the build are true, and three of them were not.

#### What was found, in order of how much it changes

**1. There is no library object, and `npkc` exit 0 is not the check it looked
like — RX-115.** All eight files in `src/` compile at `npkc` exit 0. All eight
are refused by `llc`: `use of undefined value '@npk_failsafe'`. Counted rather
than inferred — `npkc` emits **seven call sites** to that symbol into every
translation unit and **no `declare` for it, ever**; a program is saved only by
its own `failsafe` producing a `define`, and a library file has nothing to
produce one and under D-248 may not. So the shape the language mandates for a
library is the shape whose IR cannot be assembled, and `npkc`'s usage line
offers no library mode. `BUILD.md` §2's pipeline could not run as drawn.

*The route is worth recording.* Acceptance item 1 said "`npkc src/lib.npk`
succeeds and emits IR". It does. Had the subcycle stopped there — as the
acceptance literally permitted — it would have closed green over a library that
cannot be built, which is precisely what registry O-N11 exists to warn about.
The four-step recipe was run because 0.0.0's dispatch insisted on it, and that
is the only reason this was found.

**2. Two of the three ways to write the umbrella do not work — RX-113.** P-7's
premise (`use` is not transitive) is correct and its mechanism was unverified.
A plain `use` re-exports nothing. A **plain `use` above a `pub use` of the same
path silently cancels the re-export**: `symtab_bind_import` declines a name
already bound and, on the same-declaration path, returns the prior binding
**without merging `SYM_PUB`**. The file compiles at exit 0, nothing is reported
at any severity, and the failure surfaces in the *consumer* as "cannot find
`ERegexPattern` in this scope". Transcript §E2 and §E3 are the same two lines in
the two orders: different behaviour, identical output. It cost this subcycle its
first experiment.

**3. `check_no_syscalls` could not have worked as specified — RX-116.** The
consumer's object has **29** undefined symbols including `npk_open`, `npk_read`,
`npk_write` and `npk_sys6`, and it contains no library code at all: they are the
prelude's, and `opt -O2` removes one of the twenty-nine. An absolute allowlist
would fail on an empty program. With no library-only object to scan (finding 1),
the check becomes a **difference against a committed baseline**, measured here:
baseline 29, consumer 29, symmetric difference empty. RX-008's rule is
untouched; only its enforcement moved.

**4. The probe suite cannot be declared in one manifest entry — RX-119.** 16 of
23 probes carry `expect-exit:` and 7 carry `expect-error:`. Read out of
`npkg/suites.npk` rather than assumed: `run_program` (:779) does not skip a file
with `expect-error`, and `run_compile` (:608) does not filter by expectation
either — `kind` selects the checker, not the file set. The split is 0.0.2's,
because 0.0.2 builds the runner and because the paths are cited by a verified
record.

**5. `accept` was the wrong stage — RX-117.** It is judged by the compiler's
`tools/check`, which RX-007 forbids importing, and it neither links nor runs.
`compile`/`positive` does both.

#### The corrections that arrived mid-task, and what they cost

Three arrived from the coordinator while the work was in progress. **Two stand
and one was itself reversed**, which is the part worth recording.

- **`buffer` is not bounds-checked — RX-118, and it stands.** Verified here
  before it was acted on: `buffer_bytes` is on `TYPE_REFERENCE.md` §23's
  *"deliberately NOT landed"* list, so there is no slice route and every byte
  goes through `buf.ptr[i]`, a `uint8->`. S-23 gains a fourth row and **`Bytes`
  gains the accessor pair `Vec` already owed** — which matters because every
  replacement this library performs is composed into a `Bytes`, from bytes a
  caller controls. It was the one structure in `src/core/` the rule did not
  reach.
- **The live escape rule is parameter-rooted, and it stands.**
  `borrows_only_param_rooted` (`escape.npk:507`, called at :425 before
  `BORROW_RETURNED`). The **pointer-shaped root** formulation is DEF-3's
  *future* rule. Both are now labelled as which they are, in RX-112, in O-N9's
  entry and in probe07's header, because quoting the wrong one as current is how
  a later cycle builds on a rule that is not in force yet.
- **`NITPICK-BORROW-012` was declared non-existent, then restored.** The first
  correction observed — correctly — that the code appears nowhere in the pinned
  toolchain; the conclusion drawn from that was wrong. It is allocated by DEF-3
  **step 2** and lives only in an unlanded worktree commit. All four sites now
  say the thing neither earlier version did: **the code cannot be reproduced
  against `950bb1d`, and its absence there is expected rather than evidence.**

**The general lesson, and it is new to this ecosystem's documents:** *a fact
about an unlanded compiler commit cannot be checked against the pin, and
"I grepped the pinned tree and it is not there" is not a refutation.* Two
sessions reached the same wrong conclusion from the same correct observation
within an hour. Where a claim concerns work in flight, the pin can only ever
confirm absence, so the source has to be named and the claim marked
unverifiable-until-repin — which is what those four sites now do.

#### Language and tooling facts this subcycle established

- **A `failsafe` may name an error that cannot reach it.** No unreachable-arm
  diagnostic (§E4). So a consumer can state a library's contract in its handler
  before the library has any callable surface — which is what makes
  `import.npk` meaningful today.
- **`(*)` and the named arms are two different rules.** §E5 omits the wildcard
  and gets `NITPICK-PICK-003` (exhaustiveness); §E6 omits one system arm and
  gets `NITPICK-REACH-002`, whose text says *"`(*)` counts for nothing here"*.
- **Several single-name `pub use` lines from one path compose**, in either
  order. So P-7's one-name-per-line surface is buildable.
- **A module name is an identifier and all eight chosen here are free.** Checked
  against `src/frontend/keywords.npk` — the generated table, not the prose — with
  `stack`, `range`, `end`, `limit`, `buffer` and fifteen others as controls to
  prove the extraction was reading the right thing.
- **`npkrt.o` defines 201 symbols**, `__divti3`, `memcpy` and `memset` among
  them, so the closed-world link needs no compiler-rt beside it.
- **A phase-ordering trap in reading diagnostics.** `npkc` stops after resolve,
  so a file with both an unresolved name and a type error reports only the
  first. An early reading of the re-export matrix concluded that `use` *was*
  transitive for types, because the type error was never reached. Every
  subsequent matrix used one consumer per symbol kind. *This is the same shape
  as the playbook's warning that a file which fails early looks fast.*
