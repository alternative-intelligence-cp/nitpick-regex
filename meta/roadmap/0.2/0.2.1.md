## 3. The steps, and what each commit carries

**Two instruments, then the build, then its pending tests, then the prose, then the record.** Steps 1 … 5 each apply
one patch, which `apply.py` STAGES, and each is committed at its block's end — exactly the staged files, with the
dispatch's `ATTRIBUTION` lines and the subject the step names. Step 0 changes nothing. This file's title is set
`RUNNING (since <date>, <stream>)` after block 0a, uncommitted, and lands with the record. Every commit: `check_refs`
clean (each block runs it once its patch is staged); `git status --short` read. **Nothing is pushed until step 7**:
GitHub runs a push's head only, so the five work commits are read in CI through the head's run, as 0.2.0's were, and
each one's green is its block's full local run.

**The order is load-bearing.** The marker before any unit carries it; the dump's check before any builder's unit leans
on it; the build before its pending tests; the prose last, stating the counts.

## 6. What will bite

- **A `decreases` measure admits one trip more than its value** (0.2.0's §1.7a): the build's `2n − 1` is a tree walk's
  `2n`, and a class's items are walked by `resolve_items`, not by it — so a pattern with no class is at the bound's edge
  and `walk-bound-short` (`2n − 2`) traps it, 108. The class walk's measure is the arena's length: room to spare, since
  only termination rests on it.
- **The AST's values are not the HIR's** (§1.3): an anchor's `a`, and three flag bits. Map each, never copy.
- **An unnamed group's name is `pat[0...0]`**, never `pat[n.pos + 3...]`, which lies past the pattern for `()` at its
  end (finding 5).
- **A `Flags` node builds nothing, and where it stood alone it leaves an `Empty`** — an alternative, a body, the root —
  while in a `Concat` it leaves nothing: `a|(?i)` keeps two alternatives and `a(?i)` is `a`.
- **`hir_build` answers HIR_NONE for an `Ast` with no root, the root unset**: read the root, not the answer alone, when a
  parse may have failed.
- **A pending unit is excused for exit 1 alone**, and 1 is a build's stop: a pending unit's case that completes and
  differs exits 10 or more, and the run is red — read the unit's case, not the marker.
- **Code past a hook runs only when the hook is filled**: the literal's range pushed before `fold_ranges`, and the dot's
  under `i`, are cycle 0.3.4's to test; no mutant here can see them.
- **`raw` before a `never fails` call whose value is used, `discard(raw f())` for one whose value is not** — `drop` is for
  `NIL`. **Case numbers stay below 91**, the first trap code, and a unit's trap is its own file.
- **A check reads its OWN tree**: `tchecks` asks each tree's own harness, `facts.sh` each copy's, `hmut` a copy's
  self-check. **`git apply` inside this checkout resolves a patch's paths against the checkout**: `facts.sh` applies with
  GNU `patch -d`, `apply.py` with `git -C "$REPO"`.
- **`apply.py` stages what it applies; commit after each block and nothing else. It dates the run once**, in
  `.internal/w021/date`: leave the file for the whole run, and a re-run under it says `ALREADY`.
- **The private LLVM is first on PATH only inside a block**, because `env.sh` puts it there: a harness run by hand
  outside a block reads whatever `llc` the shell finds — 20.1.8 on this machine since 2026-10-08 — and the runner
  refuses it.
- **In an agent's own shell `grep` is ugrep**: run the blocks through `blocks.py`. **earlyoom**; **the sandbox** — the
  gate's 4 and 6.
