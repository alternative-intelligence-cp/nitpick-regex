### 1.7a The walk's bound — measured at the rehearsal

A `decreases` measure is checked as each step of its loop begins — the compiler's D-304: *"at a loop's head, each time
its condition holds, the measure is evaluated, and the program traps `DecreasesViolated` … if it is below zero or not
smaller than at the previous trip"* — so a loop whose measure is `3 − steps` runs four steps at both legs and traps
`DecreasesViolated` (108) as it begins a fifth. The writer's measure was `budget − steps` with
`budget = 2n + 1` for an arena of `n` nodes, so the walk could take `2n + 2` steps — one node's enter and close more
than a tree's walk, which enters and closes each node once. So a leaf with two parents — a `Repeat`'s child that is
also the last member of the `Concat` holding the `Repeat`, its `next` `HIR_NONE`, so no other check sees it — in an
arena of three nodes, every one hanging from the root, was dumped as `(concat (repeat 0 - (literal 97)) (literal 97))`,
exit 0 at both legs, and that text reads back as four nodes. With `budget = 2n − 1` the walk may take `2n` steps and
the same arena traps 108. What the bound cannot see is a shared node beside a node nothing reaches: each unreachable
node gives the walk two steps of room (§7, to 0.2.1).

## 6. What will bite

- **`raw` before a `never fails` call whose value is used, and `discard(raw f())` for one whose value is not** —
  `drop` is for `NIL` (`NITPICK-TYPE-042`, measured twice while the close wrote `dump.npk`). `hir_add_group` and
  `hir_push_range` answer a value.
- **`<-h` lends what a pointer names**: `hir_get(<-out, i)` where `out` is `Hir->` (the parser's `<-out`).
- **A range view one past the text traps**: an unnamed group's name is `text[0...0]`, never `text[at...at]` with `at`
  past the end (§1.3) — the first draft of `read_group` did that and would have trapped on `(group 1` at the text's end.
- **The root is set after the text ends, not when the outermost `)` is read** — the first draft set it at the `)`, and
  `(empty)x` was refused with its root set (case 54).
- **The writer ignores `b` but checks it**: the text shows the chain, so a reader mutant that writes a wrong count goes
  red at the writer's check (94), not at the case that reads `b` (§1.7) — read a 94 in `hir_dump` that way first.
- **A `decreases` measure is checked as each step begins**, so a measure `m` admits `m + 1` steps (§1.7a): the
  writer's `2n − 1` is a tree's `2n`, and a bound written as "twice the arena" in the measure itself is two steps loose.
- **`check_no_recursion` notes six shared names** (§1.5): a note, not a finding.
- **Case numbers stay below 91**, the first trap code, and a unit's trap is its own file (one trap per program).
- **`arena` and `Reader`** (§1.3): a later subcycle that wants either name for a module or a type meets the same two
  refusals — `BUILD.md` §7 has them now.
- **A check reads its OWN tree**: `tchecks` asks each tree's own harness, and `facts.sh` each copy's. **`git apply`
  inside this checkout resolves a patch's paths against the checkout**, not a copy under it: `facts.sh` applies with
  GNU `patch -d`, `apply.py` with `git -C "$REPO"`.
- **`apply.py` stages what it applies; commit after each block and nothing else. It dates the run once**, in
  `.internal/w020/date`: leave the file for the whole run, and a re-run under it says `ALREADY`.
- **The private LLVM is first on PATH only inside a block**, because `env.sh` puts it there: a harness run by hand
  outside a block reads whatever `llc` the shell finds, and once the machine moves to 20.1.8 the runner refuses it.
- **Block 2's claim is markdown-it's**, CommonMark's lazy continuation: a GitHub view of the file agrees, but is not the
  evidence.
- **In an agent's own shell `grep` is ugrep**: run the blocks through `blocks.py`. **earlyoom**; **the sandbox** — the
  gate's 5 and 7.
