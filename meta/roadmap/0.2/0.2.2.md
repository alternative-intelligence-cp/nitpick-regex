### 1.3 The cycle README's pattern on the way down — asked of the tree's own parser

`((a{1000}){1000}){1000}` is 23 bytes. Walked from the root, as `hir_build` enters it, it holds three `Repeat`s, whose

The product is 1 000 after the first and 10^6 after the second, so the factor that first passes
`NREGEX_REPEAT_PRODUCT` is the SECOND, byte 10, in either order (finding 1); and `NREGEX_REPEAT_PRODUCT` equals
`NREGEX_PROGRAM_INSTRUCTIONS`, 100 000 each (S-12's table), which is why raising the first above the second would move
the refusal to emission (PD-108).

### 1.4 What stands between an atom and its quantifier under `x`

`(?x)(a {1000}){1000}`: the inner atom ends at byte 6 and its quantifier's `{` is at 7. `(?x)(a#c\n{1000}){1000}`: the
atom ends at 6, and the `{` is at 9. So the atom's end is not the quantifier's first byte (finding 3).

### 1.5 The language the product is written in

A `uint64` field in a `#[derive(Copy)]` struct, a `uint64` multiply and its comparison: compile and run, both legs. `=>`
from `int64` to `uint64` is `NITPICK-TYPE-009` — *"the source can be negative"*; `=>!` is the spelling. A `uint64`
multiply past 2^64 traps `IntOverflow`, 93. A local named `end` is `NITPICK-PARSE-002`.

## 3. The steps, and what each commit carries

**The product, then its memory instrument, then the documents, then the prose, then the record.** Steps 1 … 4 each
apply one patch, which `apply.py` STAGES, and each is committed at its block's end — exactly the staged files, with the
dispatch's `ATTRIBUTION` lines and the subject the step names. Step 0 changes nothing. This file's title is set
`RUNNING (since <date>, <stream>)` after block 0a, uncommitted, and lands with the record. Every commit: `check_refs`
clean (each block runs it once its patch is staged); `git status --short` read. **Nothing is pushed until step 6**:
GitHub runs a push's head only, so the four work commits are read in CI through the head's run, and each one's green is
its block's full local run.

**The order is load-bearing.** The check and its unit before the memory pair that leans on it; the mutants over both;
the documents before the prose, which states the counts.

## 6. What will bite

- **The walk refuses as it ENTERS a `Repeat`, and stops as it LEAVES a leaf** — so a refusal can come before a stop at
  an earlier byte (`(\d{1000}){1000}` is refused at byte 3, not stopped at the `\d`), and a stop the walk meets first
  hides a bomb after it. Read the node's kind, never the answer alone.
- **The quantifier is read back from `pat`**: a `Repeat`'s `pos` is its atom's, and under `x` the atom's end is not the
  `{`. `hir_build_refusal` expects the `pat` the AST was parsed from.
- **`end` is reserved** — a local named so is `PARSE-002` and a cascade; `qend` is the refusal's.
- **The control asks for 12 GB.** Run it under its cap only — `run4`, `mutants.py` and the harness each read its
  `mem-cap-mib`; a hand-built command line that forgets the cap asks the machine for the request.
- **A `decreases` measure admits one trip more than its value**; the fuzz's member walk measures `j - m`, since `next`
  runs forwards.
- **`apply.py` stages what it applies; commit after each block and nothing else. It dates the run once**, in
  `.internal/w022/date`: leave the file for the whole run, and a re-run under it says `ALREADY`.
- **A check reads its OWN tree**: `tchecks` asks each tree's own harness, `facts.sh` each copy's. **`git apply` inside
  this checkout resolves a patch's paths against the checkout**: `facts.sh` applies with GNU `patch -d`, `apply.py` with
  `git -C "$REPO"`.
- **A full run leaves `.internal/rx120/` and may refresh `harness/__pycache__/`** — the runner's own, ignored (§1.12);
  the worker's scratch is `.internal/w022/`, removed at the record.
- **In an agent's own shell `grep` is ugrep**: run the blocks through `blocks.py`. **earlyoom**; **the sandbox** — the
  gate's 4 and 6.
