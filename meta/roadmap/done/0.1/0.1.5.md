### 1.2 §8's escapes in the engines

[`refusal-syntax-reference-engines.md`](../../../research/refusal-syntax-reference-engines.md), run here. Outside a class
every engine that reads `\1` … `\9` reads a backreference — Perl, PCRE2, Python, Java, node — and Rust's `regex`
refuses each, *"backreferences are not supported"*; `\10` is three things, group 10 in Python, group 1 and a `0` in
Java, octal or a group in Perl and PCRE2. `\k<n>`, `\k'n'` and `\k{n}` are named backreferences in Perl and PCRE2, Java
and node read `\k<n>`, and `\k` before anything else is an error wherever `\k` means anything. `\G` is an anchor in
Perl, PCRE2 and Java; `\Z` is read three ways — the end or before a final `\n` in Perl and PCRE2, before any final line
end in Java (`\r\n` and U+2028 included, measured), and the end alone in Python. `\Q…\E` quotes in Perl, PCRE2 and
Java; a lone `\E` is ignored by Perl and PCRE2 and refused by Java. Rust refuses every one; Python reads `\1` … `\9`
and `\Z` and refuses the rest, and node under `u` reads `\1` … `\9` and `\k<n>` and refuses the rest. PD-53.

### 1.3 `\g`

Perl 5.38.2 and PCRE2 10.42 read `\g1`, `\g{1}`, `\g{-1}` and `\g{name}` as backreferences; PCRE2 reads `\g<1>` and
`\g'1'` as a call of group 1 (`(a)\g<1>` matches `aa`), which Perl refuses; Python, Java, Rust and node under `u` refuse
every `\g`. Since 0.1.4 nregex refuses `\g` as an unknown letter, with *"Write `g` to match it"* — wrong for every
author who wrote it in an engine that reads it. A reading settled in an early subcycle is a premise to re-measure when
the subcycle that owns the construct arrives, and backreferences are this one's. PD-54. (Perl's `\K`, which resets a
match's start, is no §8 construct and keeps Y-2's refusal; §6.)

### 1.4 Inside a class

No engine reads a group or a position inside a class. `[\1]` … `[\7]` are octal in Perl, PCRE2, Python and node
without `u` (`[\12]` is a line feed), refused by Java, Rust and node under `u`; `[\8]` is `8` in Perl and PCRE2;
`[\k]`, `[\G]` and `[\Z]` the letter in Perl, refused by PCRE2, Python, Java and Rust; `[\g]` `g` in Perl and PCRE2.
And `\Q…\E` quotes inside a class too, in Perl, PCRE2 and Java — `[\Qa]\E]` holds `]`. So in a class `\Q` and `\E` are
the quotation's refusal as outside one, and the rest stay `UnknownEscape` — the octal digits with a sentence of their
own, since *"Write `1` to match it"* is the opposite of what Perl, PCRE and Python read (PD-53, PD-56).

### 1.6 The sentences of §8's kinds, and what lookaround can be matched in

Cycle 0.1.1's sentences each say *"… at byte N is not supported:"* and then a reason, and `UnsupportedAnchor`'s begins
*"unsupported anchor"*; the checklist says *"never 'unsupported'"*, and holds four to the letter. The backreference's
says *"matching one is NP-hard in general"* — true, Aho's result, which the PLDI 2024 paper below cites — where the
checklist asks it to say the pattern could not be matched in linear time. **The lookaround's says it *"cannot be matched
in linear time"*, and `COMPAT.md` K-1's example says the same; it is false as stated.**
[`lookaround-linear-time.md`](../../../research/lookaround-linear-time.md), the researcher's digest, ten fetches: Mamouras
and Chattopadhyay (POPL 2024) match regular expressions with arbitrarily nested lookahead and lookbehind in O(m·n),
*"where m is the size of the regular expression and n is the length of the input text"*; Barrière and Pit-Claudel
(PLDI 2024) give two linear algorithms, one for captureless lookbehinds in any language; V8's linear engine reads
captureless lookbehinds behind a flag. RE2, Rust's `regex` (measured: *"look-around … is not supported"*) and nregex
read none, and the general algorithms need right-to-left passes or memory that grows with the haystack. So the
sentence says what nregex's automata do, and the theory goes to the author (§6). PD-56.

### 1.7 `\Z`, `(?R)` and `\b{…}`, read by the neighbours

0.1.4 handed on two sentences that meet Rust's syntax. **`(?R)`** is PCRE's and Perl's recursion and Rust's CRLF mode:
*"`R` enables CRLF mode: when multi-line mode is enabled, \r\n is used"* (regex 1.13.1's documentation), which nregex
has not. **`\b{start}`** — `\b` then a brace that begins no bound, `BadRepeatBounds` today, *"Write `\{` to match a
brace"* — is a word assertion in Rust (`\b{start}`, `\b{end}`, `\b{start-half}`, `\b{end-half}`), and Perl reads
`\b{wb}`, `\b{sb}`, `\b{gcb}`, `\b{lb}` and `\B{wb}` as Unicode boundaries and refuses any other name in the braces,
`\b{2}` too; PCRE2 and Python read `\b` and then the braces as text. **`\Z`**'s three readings are §1.2's. PD-56, PD-57.

### 1.8 `regex_escape` and Rust's `regex::escape`

Nothing says what `regex_escape` writes. Rust's (regex-syntax 0.8.11, `escape_into`) writes a `\` before eighteen bytes
— `\ . + * ? ( ) | [ ] { } ^ $ # & - ~` — so its text is a literal in a pattern and between `[` and `]`; it leaves white
space bare, and regex-syntax reads `(?x)a b` as `ab` (measured), so under `x` an escaped `a b` matches `ab`. nregex's
`x` skips the same six white-space bytes (Y-42), refuses Y-42's twenty-one white-space codepoints past ASCII, and
refuses white space and `#` in a class (Y-39). And a text that is not well-formed UTF-8 must not be decoded: the
overlong `E0 82 85` decodes to U+0085, one of the twenty-one, and writing `\x{85}` for it would make the pattern match a
codepoint the text never held. PD-55.

## 3. Steps, in order

**Each step is one block and one commit**, as in 0.1.4: `apply.py` stages exactly the patch's files, the block measures
what the step claims and runs the full harness and `check_refs`, and the worker commits with the message given and the
dispatch's `ATTRIBUTION` lines. Nothing is pushed until step 9. This file's title is set `RUNNING (<date>)` after
block 0a and lands, with its record, in the record commit.

**The order is load-bearing.** The carried items first (step 1): they touch no code, and O-A3 is a question, not a
decision. Then the refusals (step 2), which make the kinds §8 names reachable from a pattern, before `\g` (step 3),
which reverses a reading 0.1.4 settled and is strikable alone. `regex_escape` (step 4) before the sentences (step 5),
which name it. `\b{…}` (step 6) after them, since its sentence is one more. The prose (step 7) after all, since it
states their counts. **`check_refs` is run at every step**, and each step cites its decision in markdown in its own
patch — PD-53's, PD-54's and PD-57's in `SYNTAX.md` and `COMPAT.md`, PD-55's in `SYNTAX.md`, `API.md` and `COMPAT.md`,
PD-56's in `SYNTAX.md`, `COMPAT.md` and `UNICODE.md` — and no patch names a decision a later step declares.
