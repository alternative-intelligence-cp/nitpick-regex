are the same blindness in other spellings, and the left side is the boundary taken from its other side. `nitpick-time`'s

### 1.3 Escapes in the engines

The digest's table, run here: Rust reads `\x41`, `\x{1F600}`, `A`, `\U0001F600`, `\a \t \n \v \f \r` and `\`
before ASCII that is neither a letter nor a digit as codepoints — and `\ `, a space, is how its documentation writes a
space under `x`. The engines part on `\0` before a digit (octal in Perl, PCRE2, Python and Java; refused by Rust; and
under §1 as written here it would be U+0000 and the digit, `\012` matching U+0000 `1` `2` where four engines match a
line feed), on `\x4` (U+0004 in Perl and PCRE2), on `[\b]` (a backspace in Perl, Python, PCRE2 and node; refused by Rust
and Java), on `😀` (one codepoint in Java and node; two lone surrogates in Python; refused by Rust) and on
`\é`. `\e` and `\0`, §1's, Rust refuses and Perl, PCRE2 and Python read as U+001B and U+0000. `\u{41}` is Rust's and
node's second spelling of `\x{41}`. Every letter no rule assigns — `c g h i j l m o q y` and `C F H I J K L M N O R T V
X Y` — Rust refuses; Perl reads most as the letter. The checklist's *"`\x41`, `\x{1F600}`, `A`, `\U0001F600`"*: the
third is `A`, decoded when the list was written (`46d870d`, the plan's first commit) — every other item names an
escape. PD-48.

### 1.4 `\<` and `\>` are Rust's word assertions

Since cycle 0.1.1 (RX-183, Y-2) `\<` has been `<` here. Rust's `regex` 1.13.1 documents *"`\b{start}, \<` start-of-word
boundary assertion"*, and regex-syntax 0.8.11 keeps `<` and `>` out of what a `\` may escape *"since the escape sequence
is significant"*; GNU `grep` 3.11 reads them as word boundaries. Measured on `a <b>`: Rust's `\<` matches the empty
positions 0 and 3, Perl's, Python's, Java's and PCRE2's the `<` at 2 — as this parser did. Rust refuses `[\<]`. No test
here uses `\<` or `\>`, so the reading changes nothing pinned (block 4). PD-49.

### 1.5 Flags

Rust refuses `(?ii)`, `(?i-i)` and `(?xx)` (*"duplicate flag"*), `(?-)` and `(?i-)` (*"dangling flag negation
operator"*), `(?--i)` and `(?i-m-s)` (*"flag negation operator repeated"*), `(?)`, and `(?i)*` (*"repetition operator
missing expression"*). `a(?i)b|c` matches `C` in Rust, Perl and PCRE2 — a flag holds across `|` to the group's end —
and `(a(?i)b)c` matches `aBc` and not `aBC`. Rust's `U` (swap greed) and `R` (CRLF mode) are flags nregex has not; `(?R)`
is already `RecursionUnsupported` here (Y-30). The parser's `Frame` carries `flags`, which `push_group` copies into a
group's frame and `vec_pop` restores at its `)`, so scope is the stack's — but `close_group` built the `Group` node from
the frame being closed, whose flags a `(?i)` inside it changes; and a `Concat` or `Alternate` is built where its list
closes, so it carries the flags in force there (block 5's `parse_flags` pins each). PD-50.

### 1.7 `(?-u)`

Rust (regex-syntax with `utf8` off): `(?-u)é`, `(?-u)\x{E9}` and `(?-u)é` are é's two UTF-8 bytes; `(?-u)\xE9`

refusal to name the codepoint, which today's sentence does not. Y-26 reserves `AST_FLAG_BYTE` for *"a `Literal` that

## 4. What will bite

- **The cursor has one byte of lookahead and no rewind** (RX-173). `escape_cp` peeks the byte after the `\` and reads
  it only when it names a codepoint, so a caller that finds it unread knows it is a class letter, an anchor, `<`, `>`
  or unknown. `\0`'s digit check peeks the byte after the `0`, and its refusal spans it without reading it.
- **A value stops growing past U+10FFFF** in `hex_escape`'s braces and in `unicode_escape`: without the stop, twenty hex
  digits trap `IntOverflow` (§1.10's `hex-no-stop`). A later edit to either loop keeps the test.
- **`x` skips only where a construct may begin.** The skip is the first branch of `parse_run`'s loop; every reader a
  construct calls — an escape, a head, a bound, a name, a quantifier's `?` — reads its bytes as without `x`. Moving the
  skip into one of them would read a shape the engines read two ways (§1.6).
- **`literal` answers a refusal now** (the white space and the byte mode it checks); its caller passes it on, as every
  other reader's caller does.
- **`stack`, `end`, `range` and `in` are reserved**; the new code uses `minus`, `named`, `fl`, `cp`, `hi`.
- **An exit status is one byte**, and the units' cases run to 90 and no higher, since each unit's `failsafe` arms exit
  91 and above; every assertion is through a value that is not vacant — no new kind is `PatternErrorKind`'s first
  variant, and `Flags`, `Literal` and `Anchor` are not `AstKind`'s — and an offset of 0 is asserted only beside a kind
  and a length.
- **A NUL or a codepoint a reader cannot see never goes raw into a test's source.** A pattern holding one is a byte
  array (`parse_refusals.npk` case 39) or a Nitpick escape, `\u{A0}`; `shown` names such a codepoint in a sentence as
  `U+` and hex.
- **`apply.py` stages what it applies.** Commit after each block and nothing else: `git status --short` first. A STOP
  writes nothing. A re-run on a later day STOPs where it would say ALREADY (the dates differ).
- **The mutants edit a copy**, `$A/ctl/mut_<name>`, removed after each; a mutant whose old text is not in its file
  once says so and runs nothing — a changed line is a mutant to re-cut, never a silent pass.
- **In an agent's own shell, `grep` is a function that runs ugrep**; the comparator's fresh `bash -c` has GNU `grep`
