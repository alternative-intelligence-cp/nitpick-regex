## 1. What was measured — the facts this plan rests on

All at `5fbaf4a`, block 0b re-deriving each.

### 1.1 The starting tree

0.1.1's record, `11b28ab`: `260/260`, decisions through RX-187, O-R3 open with its gate met — the compiler refuses an
impl that adds `move` to a lent parameter (`NITPICK-TYPE-014`, RX-176) and `vec_get`'s bound is the prelude's `Copy`
(RX-177). `vec.npk` declares `pub struct:Vec<T>` and fourteen generics, `vec_get` alone bounded.

### 1.2 The shape is expressible, and every verb must say it

`pub struct:Vec<T: Copy>` compiles. With the struct bounded and nothing else, each of the thirteen generics that
names `Vec<T>` without the bound is `NITPICK-TYPE-017` at its definition — *"`T` does not implement `Copy`, which
`Vec`'s parameter `T` requires"* — so the bound is written on every verb (`vec_get` has it). The compiler's §3.2
says why: a generic body is checked once, against the bounds it declares.

### 1.3 What it changes: no code for a `Copy` element, and twelve files

With every verb bounded, every file under `tests/` that imports `src/` keeps its verdict but twelve, and **the IR of
all seventy-two programs and roots under `src/`, `tests/unit`, `tests/conformance` and `harness/selfcheck` that
compile before and after is identical** (block 0b's `irsame`; measured byte for byte at planning too). The twelve:

- the ten `vec_owning_*` units — seven, one per verb, and the managed-half pair `vec_owning_freed` /
  `vec_owning_leak` with their control `vec_owning_freed_small_rounds` — from `compiles` to `NITPICK-TYPE-017` at
  four to six sites each;
- `vec_unit.npk`, whose `Vec<string>` section (exits 130, 131) is refused at six sites;
- `tests/rejection/vec_owning_get_moves_out.npk`, from one site (its `vec_get` call) to five.

O-R3 counted "the seven owning-element measurement units". The managed-half pair and its control instantiate
`Vec<string>` too.

### 1.4 Every consumer, and every element that is not `Copy`

At `Vec<string>` the refusal comes at every site: the type where it is first written (once per distinct instance
in a program), each turbofish, and each verb's call, the diagnostic naming the verb — *"`string` does not implement
`Copy`, which `vec_push`'s parameter `T` requires"*. A consumer struct's field, a parameter and a generic wrapper's
unbounded `Vec<U>` are refused the same way. As `T` itself, `Bytes`, `Vec<int64>`, `cstring`, a pointer
`int64->`, a slice `uint8[]`, an optional `int64?` and a fixed array `int64[4]` are each `NITPICK-TYPE-017` at the
type, the turbofish and the verb.

### 1.5 The check is half a belt

`Copy` is the compiler's "drops nothing", and S-23a asks more: "drops nothing **and holds no block of its own**".
The compiler's `Copy` passes a member that holds no body BY KIND (D-327), so a `#[derive(Copy)]` struct holding a
pointer `int64->` or a slice `uint8[]` compiles as a `Vec` element, and `check_vec_elements_own_nothing` fails it
by name — a pointer holds a block. The reverse: a struct of scalars that does not derive `Copy` is
`NITPICK-TYPE-017` at its `Vec`, and the check clears it. So the compiler is the rule for the first half and the
check its belt, and the check is still the rule for the second half. (A `#[derive(Copy)]` over a `cstring` member is
`NITPICK-DERIVE-006` — D-328 made `cstring` own.)

### 1.6 `vec_free_owning` has no reason left

At every `T` the type admits, `vec_free_owning` does what `vec_free` does in O(`count`) where `vec_free` is O(1):
each `move(v.items[j])` is a copy and `drop_element` drops nothing. Its callers are the ten units, `vec_unit`'s
section, and `vec_oob_free_owning_after_free.npk` — RX-144's unit for the guard's worse half. `src/` never calls it;
`core.npk` re-exports it; `src/lib.npk` never reaches it. Removed, every remaining program's masked IR is identical.

### 1.7 Four consequences O-R3 did not list

- **The element check misreads the declaration.** It exempts `vec.npk`'s own `Vec<T>` over that file's type
  parameter, and `struct:Vec<T: Copy>` puts the bound inside the brackets: unchanged, the run fails on
  `src/core/vec.npk`'s declaration as an element whose `T` is "a bare type parameter". The exemption reads the
  parameter before its bound (step 1).
- **A fill becomes expressible.** `vec_init_zeroed`'s comment records a generic `vec_fill` refused
  `NITPICK-TYPE-046`; under `T: Copy` one that copies its `x` into each slot compiles and runs (block 0b, exit 7 for
  7). None is written — nothing needs a value but zero.
- **The managed-half pairs.** `nitpick.toml` says the unit suite holds "the managed-half PAIRS … required to end
  DIFFERENTLY under the same cap", "the only gate on half of this cycle's memory obligations". With the `Vec` pair
  retired, the pair left is `bytes_copy_string_empty` / `_nonempty` — and both of its halves end 0 since `c3bdae2`
  fixed the leak its empty half caught, so that sentence was already stale for it. Step 1 dates both statements. The
  runner's `mem-cap-mib:` stays in use by that pair.
- **Every later element type derives `Copy`**: `HirNode`, `ClassRange`, `Literal`, `GroupInfo` (`HIR.md`), and
  `Inst`, `InstKind`, `ByteSet` (`COMPILE.md`, C-1) — `ByteSet` does not yet. Step 4 says so where they are
  specified.

### 1.8 The counts

`src/core/` from 48 unit programs to 37; `tests/unit/` from 63 files to 52. The element check's exempt count 15 →

## 4. What will bite

- **A generic that names `Vec<T>` states `T: Copy`**, or it is `NITPICK-TYPE-017` at its definition — every verb

  `AstKind` do; a struct of scalars that does not is refused at its `Vec`.

  call.** A second `Vec<string>` written as a parameter after a field is not reported again (measured). The
  fixture's fourteen sites are its one instance and thirteen calls.
- **Leave `TMPDIR` unset.** Pointed inside this repository, the harness's reproducibility step (B-4) failed in every
  self-check case — *"two builds of the same tree from different working directories produced DIFFERENT IR -- 57462
  and 57782 bytes"* — on the unchanged tree as on the changed one; under the default `/tmp` it passes. Measured at
  planning; the cause is not established (§6).

  STOP writes nothing. A re-run on a later day STOPs where it would say ALREADY (the dates differ).
- **The fixture's positions are measurements**, 51:5 … 66:18; a header edited by a line moves all fourteen.
- **The IR comparison masks two things only**: the site-line table, which a comment line moves, and the number in
  each generated `npk.drop.N` / `npk.vacant.N` name, which a removed declaration moves. Any other difference is a
  stop.
