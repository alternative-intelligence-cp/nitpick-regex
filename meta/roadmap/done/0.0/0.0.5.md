## A. The findings — everything cycle 0.0 found that was not a probe verdict

Numbered so a sibling repository can act on one without reading the rest. Every
one was **measured here**, and the measurement is named. Where a finding
contradicts something this repository previously shipped, that is said rather
than quietly fixed.

### The language

**A1. `never fails` may carry `requires`, `ensures` and `limit`.** The compiler's
**D-241** retired D-163 rule 2's contract row on 2026-09-03, because a
`never fails` body already admits the trap channel. **This repository shipped
the opposite as a *permanent* `NITPICK-TYPE-037`** and wrote it into cycle
0.0.0's record as deciding which `src/core/` functions could carry an obligation
at 1.5 — while `VERIFICATION.md` §4's own P-2 example was `requires …
never fails`, the shape the claim forbade. RX-127.

**A2. `limit<Rules>` is live since the compiler's 1.5.2, and it charges every
consumer a `failsafe` arm.** A limited binding **anywhere in the reachable call
graph** makes `(LimitViolated)` mandatory in every consuming program — measured
with controls at **both** `pub` and module-private visibility, because
reachability follows the call graph and not visibility. The violation takes
D-241's trap route, so `?|`, `?!` and `is_err` at the call site cannot decline
it: an explicit `?| 55i32` over a violating call still exits **97**. This
library therefore declares no `limit` at all (S-24). RX-127.

**A3. A `/` or `%` ANYWHERE in a module arms `DivByZero` and `DivOverflow` in
EVERY importer.** Measured with a control: two test programs that call only
`bytes_init`, `bytes_push` and the accessor pair were refused
`NITPICK-REACH-002` for both arms **merely for importing** a `bytes.npk` whose
`bytes_put_uint` used `x / 10u64`. **Neither arm could ever have fired** — the
divisor was a literal and the operands unsigned — because the reachability walk
does not reason about values. **Any library promising a small `failsafe` bill
owes a sweep for division under `src/`.** RX-132.

**A4. A generic body is checked at EVERY instantiation (D-264), so a generic
operation that COPIES its element cannot exist at any `T`.** `vec_fill<T>(v, n,
x)` is `NITPICK-TYPE-046`: *"some of which own storage — a copy here would leave
two owners at those"*. **It is not a signature to fix.** `move` does not rescue
it, because the value is consumed by the first slot. The fill that works is
`vec_init_zeroed<T>` over `calloc` — the one that needs no value. RX-129's
neighbour, recorded at 0.0.4.

**A5. The 64-bit literal envelope is SIGNED.** `10^19` is `NITPICK-LEX-004`
*"outside the 64-bit literal envelope (D-148)"* **even as a `u64` that holds
1.8e19 comfortably**. The known rule — that `int64`'s minimum cannot be
spelled — has an upper-end twin nobody had written down, and a power-of-ten
table is exactly where you meet it. Build the value arithmetically. RX-132.

**A6. A reserved word is refused as a BINDING name and ACCEPTED as a struct
FIELD name.** `int64:end = 5i64;` is `NITPICK-PARSE-002`; `pub struct:Match = {
int64:start; int64:end; };` compiles, is built by struct literal, is read as
`m.end`, links and runs. Measured at **all three kept pins**, so this is not an
expiry — **the opposite claim was false the day it was written**, and it reached
seven sites over five subcycles. RX-134, and see B4 for why it survived.

**A7. `>>` is arithmetic on a signed operand and logical on an unsigned one, and
`>>>` does not parse** though the operator table lists it. Load-bearing here:
`byteset.npk`'s `b >> 6` and `b & 63` replace `/ 64` and `% 64` under A3, and
they are only exact because the operand is unsigned. 0.0.0 probe 11.

**A8. An `Optional` is not `pick`-able.** `pick (m) { (NIL) {…}, (Match:g) {…} }`
is `NITPICK-PARSE-005` — an `Optional` has no readable members. Test `== NIL`,
read with `??`. Caller-visible on most of `API.md` §1, because `regex_find`
returns `Match?`. 0.0.0 probe 06a.

**A9. `#[derive(Eq)]` and `#[derive(Ord)]` on a payload enum WORK and read every
payload field** — at `94874ce` and after. At `950bb1d` `Eq` was refused
`NITPICK-TYPE-034` and `Ord` compared **tags only**, so `Repeat(2,5).cmp(
Repeat(9,9))` answered `Equal`. **But `.eq()` returns `Result<bool>`**, so
`if (a.eq(b))` is `NITPICK-TYPE-007` — replacing a hand-written comparison with
a derive threads an error channel and charges the budget. RX-125.

### The instruments

**A10. `npkc` exit 0 does not mean a program is well-formed, and there is no
library object.** Every file in `src/` compiles at exit 0 and **every one is
refused by `llc`**, because a library file cannot define `@npk_failsafe` and
`npkc` never emits a `declare` for it. The library reaches the compiler only
through a program root. **Run all four steps — `npkc`, `llc`, `ld.lld`, the
binary — on anything you claim compiles.** RX-115.

**A11. `npkc`'s exit codes are an alphabet and `2` is not a refusal.** `0`
success; `1` refused **with diagnostics**; `2` the driver could not proceed and
**judged nothing**, with an empty stderr; `3` a trap. A test expecting 1 that
receives 2 was never compiled and proved nothing. **And a missing import exits
`1` with `NITPICK-RESOLVE-005` — the very code a rejection fixture expects** —
so a rejection test whose path is typo'd passes for the wrong reason, and only
code-set equality tells the two refusals apart.

**A12. `exit 0` proves no `wild` block was left live and proves nothing else.**
D-151 counts `wild` blocks, D-188 counts live drivers, **and neither sees a
managed body**. A `Vec` freed without dropping its owning elements exits 0.
**Where the obligation is managed the gate is a MEMORY CAP** — `vec_free_owning`
and `vec_free` under one 64 MiB cap must end **differently**, 0 and 92
(`HeapOom`). RX-110, RX-123, RX-126.

**A13. A low `ulimit -v` measures the loader, not the program**, so every
address-space bound needs a `/bin/true` control at the same cap. The capped
gate above runs that control on every capped file, and `mem-cap-mib:` is the
expectation header carrying it.

**A14. The prelude trim collapsed the empty-program floor from 29 undefined
symbols to 2.** D-262 emits a prelude item only if it is **referenced**, so
`SYMBOLS.txt` went 29 → 2 and `EDGES.txt` 237 → 2. **Any repository whose
no-syscall check is "equal to the baseline" now fails on the first program that
allocates** — a four-line program making one `wild` block already differs by
three symbols. The rule survives as a **reviewed residue list with a reason per
line, checked both ways**; the equality does not. RX-131.

**A15. RX-120's ecosystem-wide finding HAS EXPIRED, and the transcript proving
it is committed.** RX-120 said the undefined-symbol scan *cannot see a syscall* —
floor and syscaller both 29, difference empty, because `npk_sys6` was already
the prelude's. **At `3d15ac9` the floor is 2, the syscaller is 3, and the
difference is exactly `{npk_sys6}`.** Both pins are run back to back in
`harness/baseline/RX120.txt`. **RX-120's decision stands**: the call-edge scan
names the *calling function*, which no symbol set can at any pin, and it
survives a prelude that emits `npk_sys6` again. Four sibling repositories carry
the expired clause as current fact and each needs its own re-measurement.

**A16. Two of eleven residue entries were added by REASONING and the check
refused both.** `npk_chain_push` ("the `defer` pair travels together") and
`npk_int_to_string` ("interpolation must call the integer formatter") were
written from inference; the both-directions half of the check refused them
because **no scanned program references them**. That is a named-exemption list
caught at the moment of writing rather than three cycles later — and it happened
to the session that had just built the mechanism. RX-131.

**A17. `memset` is minted by `opt -O2` and absent at −O0.** The one residue
entry whose provenance is the optimiser rather than the source: `buffer_new`
zeroes and `calloc` zeroes, and at −O2 the optimiser recognises the loop and
emits a `memset` libcall. **An IR-shape claim measured only after optimisation
is a claim about the optimiser.** Take the number at both levels or say which
one you took.

**A18. The compiler's emission is INVOCATION-independent and
TREE-POSITION-dependent.** Four controls: three invocations sharing no working
directory and no argument form emit **byte-identical** IR; the same file copied
to a directory whose name is eight characters longer emits **24 more bytes**,
one per character per site row. D-236 renders every site path relative to the
**manifest root**. So *"an emitted `.ll` is path-dependent"* is true as an
observation and misleading as a rule — and the sharper statement is what makes a
cross-machine digest comparison legitimate. RX-133.

## C. Self-check case 9, and what a decaying expectation actually does

**The claim to be checked:** case 9 predicted in its own header, on 2026-09-04,
that `npk_ralloc` would become legitimate at 0.0.4; it did; and the case *"would
have gone GREEN rather than reporting that its premise had expired"*.

**Reproduced rather than reasoned about.** The old fixture was restored from
`e35ba16`, case 9's `must_say` was returned to `` `npk_ralloc` ``, and the
harness was run against today's tree — where `npk_ralloc` **is** a reviewed
residue entry.

```
FAIL  case 9: a program needing a floor symbol neither the baseline nor the residue list has
      the harness failed it (exit 1) but never said '`npk_ralloc`'. A non-zero exit
      alone is not enough: it would also be produced by the runner crashing for an
      unrelated reason, which is a passing case whose red is unreachable.
```

**So the case did NOT go green, and the mechanism that caught it is `must_say`.**
The inner run exited 1 — but *for an unrelated reason*: in a tiny case tree only
2 of the 11 residue entries are referenced, so the both-directions check reported
the other nine. **Without `must_say`, case 9 would have been satisfied by that
red and gone green on a failure that had nothing to do with it.**

**Three things follow, and only the third is a gap.**

1. **The prediction in the 0.0.4 report is too strong.** It was written from
   reasoning; the measurement says the case reddens either way — by `must_say`
   if the harness fails for the wrong reason, and by *"THE HARNESS PASSED IT"*
   if it does not fail at all.
2. **The reason it holds is a mechanism this repository already built**, and it
   should be stated as the general rule: **a self-check case asserts the words
   its red must contain, not merely that a red happened.** Every case here names
   its own fixture file for exactly this reason.
3. **The gap is the DIAGNOSIS, not the detection.** The red reads *"the harness
   failed it but never said X"* — which describes a **regression in the runner**,
   and sends a reader to debug the harness. What actually happened is that the
   **case's premise expired**. Those want different words.

**The cheap mechanism, proposed and deliberately NOT built here.** Give a `Case`
an optional `premise` — a callable returning `None` or a string — checked
*before* the case runs, so an expired premise reports `PREMISE EXPIRED: npk_ralloc
is now on the residue list` instead of a failure that looks like a broken
runner. Roughly ten lines. **It is not built in this subcycle** because the
self-check is the instrument the cycle's gate rests on, this is the close, and
the detection it would add is **zero** — the case already reddens. It buys a
better sentence, and that is a 0.1 item, not a 0.0 one.

**And case 9's own fix at 0.0.4 is the better answer anyway, because it is
structural**: the fixture now leans on `npk_mono_now`, chosen to be **unaddable**
rather than merely unused — D-076 and this ecosystem's determinism rule mean no
clock may ever join the residue list — **so the premise cannot expire twice.**
Prefer an expectation whose premise cannot decay over a mechanism that reports
decay.

## D. What cycle 0.0 taught

*Written at the close, for a reader who was not here and cannot ask anything.
This section and §A are the cycle's most durable output — the compiler's
equivalents are the reason its later cycles cost less than its earlier ones.*

**1. A probe that fails is the cheapest thing this cycle produced, and a probe
that REFUTES ITS OWN HYPOTHESIS is the most valuable.** Two did. `probe06b` was
planned as *expected refused* and was **accepted** — the plan's instruction to
stop and re-plan `API.md` §2 was correctly **not followed**, because the
acceptance is a compiler defect (O-N9) rather than a licence. `probe08b`'s own
header claimed the unguarded read *traps*, and the probe written to prove it
**disproved it**: it returns an unrelated heap word. That second one rewrote
`SAFETY.md` §1, added §5.3, and made an accessor pair load-bearing —
**a whole safety rule that existed because somebody ran the program instead of
believing the table.** Rename the probe when its hypothesis dies, and keep the
history in its header; do not tidy it away.

**2. The specification is the authority, and it is also the document most likely
to be stale.** Both are true at once and the second does not weaken the first.
Six of 23 verdicts had a consequence that landed in an open question, a record
or `CLAUDE.md` and **not in the rule that owns the topic**. The mechanism is
always the same: *the discovering document is not the owning document*, and each
one reads complete by itself. **Budget a reconciliation step at every cycle
close and do it by reading, not by grepping** — every one of these six was a
claim about tense or truth, containing no wrong token.

**3. Measure the extent, not just the existence.** A defect's *existence* is one
measurement and its *extent* is a different one, needing its own controls. RX-127
took three: `pub`, module-private, and an explicit fallback. RX-132 took a
control that never calls the function containing the division. **Understating an
extent fails silently and overstating one costs a message.**

**4. Prefer a check that fails to a rule that asks for care — and then check that
the check applies.** This cycle wrote five failing tree checks and a self-check
that runs first and proves the runner can fail eight ways. It also found, four
separate times, that **a check which did not apply is byte-identical to one that
passed**. So: print the denominator, print how many units a scan skipped and
why, and give any predicate that *gates* a check a positive and a negative case.

**5. A committed transcript is worth more than the sentence it supports, and the
gap shows up exactly when the claim travels.** RX-120's original measurement had
a table; its *expiry* was asserted in three places with no transcript — and the
expiry was the half being propagated to four sibling repositories. **A claim
other repositories will act on is reproducible by running a file.**

**6. Name the commit, not "the pin".** Three sites said *"measured at the pin"*
and the pin moved twice underneath them. Two probe verdicts have already
reversed under re-pins (RX-125's derives, RX-127's `limit<Rules>`), and a third
claim expired (RX-120). **A measurement against a moving compiler is dated by its
commit or it is not dated**, and *"is this current behaviour or behaviour at a
superseded pin"* is a question every claim here must be able to answer.

**7. The error budget is charged by three things and only one of them is a
declared `error:`.** An `error:` (S-8), **arithmetic** — `%` and `/` each add
two arms — and a **contract clause** — a `limit<Rules>` adds one. **A budget
audit that counts only `error:` declarations is counting one of three**, and the
other two are invisible in the API. This is the finding most likely to bite a
sibling, because every library here promises a small `failsafe` bill.

**8. Reachability is import-scoped, so a module's contents are its importers'
problem.** A division in `bytes.npk` charged programs that never called the
function. A limited binding charges consumers at module-private visibility.
**Module decomposition is part of the API**, not an implementation detail.

**9. `exit 0` is a narrower gate than four different sentences in this
repository's own plan claimed.** It sees `wild` blocks and live drivers and
**nothing else**. Every one of those four sentences was written by someone who
knew the rule. **Where the obligation is managed, the gate is a memory cap** —
and it needs a `/bin/true` control, because a low cap measures the loader.

**10. The mechanical warnings are not things to remember, and this cycle proved
it by paying them anyway.** `npkc` writes IR to stdout; `$?` after a pipeline is
the filter's status. Four sessions in this ecosystem violated the second
*having just read the warning*. **The fix is structural: pair every captured
status with the artefact it should have produced** — a refusal that wrote no
`.ll` reporting exit 0 is falsified immediately, and every violation so far was
caught that way and none by recall.

**11. What went right, and it is worth naming because it is repeatable.** The
order — probes, then harness, then primitives, then close — meant every language
surprise was met by a ten-line program instead of by a half-built engine. The
self-check existed **before** the suite it judges. `src/core/` was written
against a runner that had already been shown able to fail. **Nothing in this
cycle was blocked on a question**, which is what the cycle map promised, and
that held.

**12. What cycle 0.1 should expect.** It is the first cycle that writes real
algorithmic code, so the three constraints that cost the most here move from
theoretical to daily: **no `/` or `%` under `src/`** (a `{n,m}` parser wants
one), **no native recursion** (a parser wants it more than anything), and **the
accessor pair** (an arena walker will reach for `.items[`). All three now have
a check that fails. That is the difference between cycle 0.0 and cycle 0.1.
