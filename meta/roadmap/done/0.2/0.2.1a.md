each apply one patch, which `apply.py` STAGES, and each is committed at its block's end — exactly the staged files, with
the dispatch's `ATTRIBUTION` lines and the subject the step names. Step 0 changes nothing. This file's title is set
`RUNNING (since <date>, <stream>)` after block 0a, uncommitted, and lands with the record. Every commit: `check_refs`
clean (each block runs it once its patch is staged); `git status --short` read. **Nothing is pushed until step 6**:
GitHub runs a push's head only, so the four work commits are read in CI through the head's run, and each one's green is
its block's full local run — step 1's at `5fbaf4a`, the others' at `7e91730`.

**The order is load-bearing.** Step 1 before the pin, so the old compiler can say the re-spelling changes nothing; step
2 makes the tree green at `7e91730`; step 3's CI pin after the tree is adopted and before the push; the prose last,
stating what steps 1 … 3 made true.

## 6. What will bite

- **A helper's LLVM is its pin's, inside its own subshell.** `harness`, `tools`, `cases` and `facts.sh`'s `legs` put the
  private 20.1.2 first on PATH for `5fbaf4a` only; nothing else in a block sees it. A harness run by hand outside a block
  reads whatever `llc` the shell finds, and the runner refuses any release its manifest does not name.
- **Step 1's tree is RED at `7e91730`** — its manifest still pins 20.1.2, and probe 06b's return is step 2's — and that
  is the design: its green is `5fbaf4a`'s. Do not push between steps.
- **A site is a measurement**: `pattern_error_literal.npk`'s literal is at 29:22 and `cursor_pos_write.npk`'s write at
  23:5 after step 2; a header edited by a line moves each, and the harness says so.
- **`fixed` before a return type means nothing at `5fbaf4a`** (DEF-247), and **a write through a `fixed` slice, or a
  `fixed` parameter reassigned, compiles there in silence** (DEF-230, DEF-248). The old pin's green says the
  re-spelling changed no answer; only the new pin's census says the re-spelling is true.
- **A copy of the tree is not in the checkout's position**: its `rx120` step finds no `950bb1d` and says SKIPPED, and its
  `check_refs` finds no `../BOARD.md`. The blocks run the checkout itself, and copies only where a block says `ctl`.
- **`git apply` inside this checkout resolves a patch's paths against the checkout**: `facts.sh` applies with GNU `patch
  -d`, `apply.py` with `git -C "$REPO"`. **`apply.py` stages what it applies; commit after each block and nothing else.
  It dates the run once**, in `.internal/w021a/date`: leave the file for the whole run, and a re-run under it says
  `ALREADY`.
- **To `check_refs` a closing bracket followed by an opening parenthesis is a link, inside code spans too**: a return
  type is written `fixed uint8[]` in markdown, never followed by its parameter list.
- **In an agent's own shell `grep` is ugrep**: run the blocks through `blocks.py`. **earlyoom**; **the sandbox** — the
  gate's 4 and 6.
