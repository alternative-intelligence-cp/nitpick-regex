## 6. What will bite

- **Both pins run under the same LLVM**, the machine's 20.1.8, so a helper's pin is its compiler and its runtime object
  alone (`leg`). A harness run by hand outside a block reads whatever `$NPKC` the shell holds.
- **Step 1's tree is green at both pins** — the rename is all the code owes — and its commit's evidence is the OLD pin's:
  that is the design. Do not push between steps.

  through `emit.py compare`, which runs the compiler's `attrnorm.py` and then `dropnorm.py`; a `DIFFERENT` line there is
  a stop, read with `--show`.

  over one tree, as block 2 does; block 1 compares two trees at one pin, where the rename moves no line.

  Block 2 shows it. Run the blocks in order, once; a block re-run out of order says STOP and writes nothing.
- **`git apply` inside this checkout resolves a patch's paths against the checkout**: `apply.py` applies with
  `git -C "$REPO"`. **`apply.py` stages what it applies; commit after each block and nothing else. It dates the run once**,
  in `.internal/w025a/date`: leave the file for the whole run, and a re-run under it says `ALREADY`.

  mutants' copies, which only compile.
