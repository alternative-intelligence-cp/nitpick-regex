## 3. Decisions taken at planning, with their reasons

**D1 — the AST is a flat POD arena indexed by `int32`, exactly like the HIR.**
`HIR.md` H-2's reasoning applies unchanged: a `Vec<AstNode>` reallocates on
growth and every pointer into it would dangle, whereas an index survives. And
**an `AstNode` may not hold a `string`**, because a `Vec` holds a `T` that owns
nothing — `SAFETY.md` S-23a, RX-155, which `check_vec_elements_own_nothing`
enforces over `src/`: a `Vec<AstNode>` whose node holds an owner fails the run.
Group names live in a `Bytes` and are referenced by offset and length, which is
what `Hir.names` already does.
*(This paragraph said until the third cycle 0.0 audit that `TYPE-046` "forces"
it. It does not: the language accepts an owning element in an array or a `Vec`,
and `vec_get` then MOVES the element out of its slot, leaving an empty one that
`count` still counts. The rule is this library's, which is why it is checked.)*
*(2026-09-26, cycle 0.0.4e — RX-168: for `vec_get` it is the compiler's too now.
`vec_get` takes `T: Pod`, and at an owning `T` it is `NITPICK-TYPE-017`, not a move.)*

**D2 — the cursor holds `uint8[]` and an `int64` offset, and it is a parameter
everywhere.** Never a return value. `string_bytes` on a local yielded a view that
escaped its owning frame **with no diagnostic** (workbench O-N9, the compiler's
DEF-3) and reading it afterwards read freed memory. The ecosystem's house rule
until that landed was *a view is a parameter, never a return value*, and cycle
0.0.4 struck `bytes_view` from `Bytes` on exactly this ground. *(It landed at
`94874ce`: at `c3bdae2` the escape is `NITPICK-BORROW-001` and a view of a
parameter is accepted — measured by the fifth cycle 0.0 audit's triage. The
house rule is still the right one for D2's cursor.)*

**D3 — every `PatternError` is built by one constructor, `pattern_error(kind,
offset, span_len, detail)`.** `SYNTAX.md` Y-10 requires a byte offset on every
error, and the only way to make a call site unable to forget one is to give it
no other way to build the value. This is cheap now and impossible to retrofit
once there are forty construction sites.

**D4 — `PatternErrorKind` is declared complete in this subcycle**, all of
`SYNTAX.md` §9's kinds, even though nothing produces most of them until 0.1.5.
Two reasons: `check_error_kinds_tested` (cycle 0.1's gate) diffs the enum
against the tests that provoke each kind, and it cannot be written against a
moving enum; and a kind added later is a kind nobody notices is untested.

**D5 — `NREGEX_PATTERN_BYTES` is checked before the cursor is built**, not
during the scan. It is the cheapest possible refusal and it bounds everything
downstream, including the arena.

**D6 — the arena's element accessor is `Vec<T>`'s, not a new one.** `ast_get`
wraps `vec_get`. Do not reach `.items[` from `src/syntax/` — see §5.

## 5. What will bite, and it is not hypothetical — every item cost cycle 0.0 time

**N-15 — A `Vec` IS COPYABLE TODAY, AND IS FIXED BEFORE THIS CYCLE BEGINS.** A
whole-`Vec` copy (`Vec<T>:w = v;`), a whole-`SparseSet` copy, a BY-VALUE `Vec`
parameter and ANY STRUCT HOLDING A `Vec` are each a second handle on the same
block: freeing both is a double free (95), and reading one after the other is
freed reads the `0xAA` poison — and through a `SparseSet` copy a member reads as
ABSENT while the count says one, with no trap (`../../../tests/unit/*_alias_*.npk`
pin each; RX-160). This cycle builds the first structs that hold a `Vec` — the
AST arena and the parser's `Vec<Frame>` state. **By the author's decision on the
board's question 9 (2026-09-25), `Vec` becomes MOVE-ONLY BY CONSTRUCTION at
subcycle 0.0.4d, BEFORE CYCLE 0.0 CLOSES AND SO BEFORE THIS ONE BEGINS.** Its
plan is 0.0.4d's; nothing here assumes its shape. So: **read 0.0.4d's record
before step 1**, because it may change `vec_get`'s signature — which takes its
`Vec` by value today — and so D6's `ast_get`; build every container-holding
struct to be MOVED, never copied; and pass a container to a callee that must not
own it by pointer (`@`/`->`). If 0.0.4d has not landed when this subcycle is
dispatched, that is a stop, not a start (W-23).
*(2026-09-25 — 0.0.4d LANDED, and it did not change `vec_get`'s signature (RX-161,
RX-162): D6's `ast_get` wraps `vec_get` exactly as planned. A `Vec`, and any
struct holding one — the AST arena, the parser's state — is move-only: a copy is
`NITPICK-TYPE-046`, a transfer is `move(...)`. A by-value parameter is a LOAN and
compiles without `move`, so use one only to READ; a function that pushes, pops or
frees takes the container by pointer, because a callee that writes through a
loan's address frees or grows its caller's block — a compiler defect
(`SAFETY.md` S-23b; `../../../tests/unit/*_alias_param_*.npk`). The copy units
this paragraph names moved to `../../../tests/rejection/`.)*
*(And two more shapes since the fifth cycle 0.0 audit, RX-167: a `for` binding
over an array of containers is the same loan, and a GENERIC function passing out
its lent `T` hands back a second owner — `TYPE-047` is not asked of a lent `T`
in a generic body (O-N22, the compiler's DEF-104). So a generic helper this cycle
writes takes `move T` or a pointer, never a bare lent `T`, and frees nothing
through a `for` binding.)*
*(2026-09-26 — cycle 0.0.4e, at compiler `c970483`: the compiler holds all of it now.
A write through a loan is `NITPICK-TYPE-085`, a generic pass-out of a lent `T`
`NITPICK-TYPE-047` (RX-169). And `vec_get` takes `T: Pod` (RX-168), so D6's
`ast_get` needs its element to implement `Pod` — for a POD `AstNode`, one line
where it is declared, `impl:AstNode:Pod = { func:pod_copy = AstNode(AstNode:self)
never fails { pass self; }; };`, which the compiler refuses for an owning struct.
`../../../tests/unit/loan_spellings.npk` runs each spelling a callee needs.)*

**N-21 — A generic helper over a generic container, outside that container's
module, does not build at `c3bdae2`**: `npkc` exits 0 and emits the instance's
type definition after its first use, so `llc` refuses the IR (`Cannot allocate
unsized type`). A COMPILER defect, reproduced by the orchestrator and relayed to
the compiler seat; the fourth audit's N-21 has the reproducer. It is the
compiler's DEF-97, fixed at its 1.6.0 step 3d (`f758995`), which the pin
`c3bdae2` does not carry. *(2026-09-26, cycle 0.0.4e: `c970483` carries it. The
fourth audit's reproducer, the same with the struct in an imported module, and a
generic helper with a `Vec<T>` local called at `int64` and at `string` each build and
run at −O0 and through `opt -O2` there, where `llc` refused all four at `c3bdae2` —
so such a helper is buildable now.)* The
harness's `llc` step catches it, so it is loud, not silent. Do not work around
it: if a design wants such a helper, record where and stop.

**At compiler `c3bdae2` every `while` states why it ends** (D-304): `decreases E`
or `unbounded`, and a loop with neither is `NITPICK-TYPE-072`. The measure is
checked in every build and a wrong one traps `DecreasesViolated`. A bound read
through a pointer — `v.count` where `v` is `Vec<T>->` — belongs in a local
first, so the verified build can discharge it (RX-150); `0.0/decreases_read.txt`
is how cycle 0.0 recorded each reading, and yours needs the same record.

**Every `failsafe` owes six identities before the program does anything** —
`HeapBadRequest`, `HeapOom`, `Unreachable`, `WildLeak`, `StackExhausted`,
`MachineFault` — **plus whatever `NITPICK-REACH-002` names for the code it can
reach**: `DecreasesViolated` for a measured loop, `LimitViolated` for anything
reaching `vec.npk`, `bytes.npk` or `sparseset.npk` (their counts carry
`ListLen`, S-24a), `ShiftRange` for a computed shift. The codes are the
ecosystem's (RX-149): 91–96, **106** `StackExhausted`, **107** `MachineFault`,
**108** `DecreasesViolated`, **109** `LimitViolated`, **115** `ShiftRange`,
**116** `RequiresViolated`, **117** `EnsuresViolated`, **99** the wildcard — and
no test's expected exit may equal an arm code it does not assert. `REACH-002`
stays hidden while an earlier phase refuses the file, so fix `TYPE-072` first
and read `REACH-002` second.

**A `Vec` holds a `T` that owns nothing** (S-23a, RX-155), and the language does
not say so. `Vec<string>` compiles; `vec_get` on it MOVED the element out and
the next read was empty, through `c3bdae2` — since cycle 0.0.4e it is refused,
`T: Pod` (RX-168); `vec_set`, `vec_remove`, `vec_swap_remove`,
`vec_truncate`, `vec_clear` and `vec_free` orphan owners invisibly to `exit 0`.
`check_vec_elements_own_nothing` is DEFAULT-DENY (RX-158): it fails any `Vec`
element under `src/` — in a `Vec<…>` or a `vec_…::<…>` turbofish — that it cannot
CLEAR as owning nothing. It clears the language's scalars, and structs and enums
declared under `src/` built only from them; it fails a `string`, any prelude
type, a pointer, a slice, and a bare type parameter. So an AST node or a parser
`Frame` holding a `string` is a red run, not a review comment — and so is one
holding a type the check cannot see, and a generic helper's `Vec<T>` outside
`vec.npk`. `SYNTAX.md` §3 names `Frame` without fields: this cycle shapes it, and
shapes it from scalars and offsets.

**`main` takes ONE parameter**: `func:main = int32(cstring[]:_~argv)` (D-089;
the compiler's 1.6.0 step 3c refuses any other form `NITPICK-TYPE-083`, its
DEF-96 — landed at `d156c4f`, in our pin since `c970483`). Spell it
`cstring[]:argv` only if the program reads `argv.len` — and then **assert the
value it derives**, `if (zero != 0i64) { exit 48i32; }`: a unit that computes
its tested index from `argv.len` tests another index the day something passes
an argument (the third audit's N-16, thirty files).

**`&{…}` interpolates only inside a backtick template.** `"&{k}"` in double
quotes is the four characters `&{k}`; `` `&{k}` `` is the number.

**A test that is correct and red because the pinned compiler is the defect** is
committed with `// pending-until: <commit> exit <N>` AND a line in
`harness/baseline/PENDING.txt` (RX-154, `BUILD.md` B-5b). The marker excuses
exactly the exit it names, on every leg and every run (RX-159) — so give the unit
an exit code of its own where the defect allows, not a shared trap code; the list
is what stops the marker's comment line moving a red out of a green run. Never
guard around the defect in `src/` instead.

**Reserved words.** `end`, `in`, `range`, `any`, `limit`, `error`, `move`,
`buffer`, `raw`, `fixed`, `Rules`, `Self`, and **`stack`**.

- **`stack` cost cycle 0.0.0 about an hour** and it is the natural name for an
  explicit-stack parser's local, which is this whole layer's shape. It is a
  MemoryQualifier beside `wild`, and **it does not fail where you write it**:
  `PARSE-002` at the declaration, then *"this `{` is never closed"* pointing at
  a brace dozens of lines away. *If a parse error claims an unclosed brace and
  the braces are balanced, look for a local named after a qualifier before you
  touch a brace.*
- **A reserved word is refused as a BINDING name and ACCEPTED as a struct FIELD
  name** — measured at three pins, RX-134. So `int64:end = …;` is
  `PARSE-002` and `struct:Span = { int64:end; };` is fine. Cycle 0.0 shipped the
  opposite claim for five subcycles.

**`src/` contains no `/` and no `%`, and `check_no_division` will fail your
commit** (S-25, RX-132). This is an **error-budget** rule, not an arithmetic
preference: a division anywhere in a module arms `DivByZero` and `DivOverflow`
in **every importer**, whether or not it calls the function containing it, and
`(*)` discharges neither. A parser wants `/` for exactly one thing — decimal
`{n,m}` bounds at 0.1.1 — and the substitute is repeated subtraction against a
descending power of ten, which `bytes_put_uint` already does; copy it.

**`src/` declares no `limit<Rules>`** (S-24, RX-127), for the same reason one
register up: a limited binding anywhere in the reachable graph charges every
consumer a `(LimitViolated)` arm it cannot decline. Bounds are checked by hand
against `src/core/limits.npk`.
*(Dated 2026-09-25, cycle 0.0.4c: `core`'s containers now carry the prelude's
`ListLen` on their four counts — `SAFETY.md` S-24a, RX-153 — so every consumer
of `vec.npk` owes `LimitViolated`, the parser included, and its `failsafe`s
name it. The parser's own rule is unchanged: no `limit` of its own, and no
`Rules` of this library's.)*

**No `.items[` outside `src/core/vec.npk` and no `.ptr[` outside
`src/core/bytes.npk`** — `check_accessor_confinement`, new at 0.0.5. It is not
style: `Vec<T>.items` is a `wild T->` and D-070 emits **no bounds guard** for a
bare pointer, so an out-of-range index **reads and returns a heap word at exit
0**. The accessor pair is the only bounds check this library has.
*(Dated 2026-09-25, cycle 0.0.4c: `Vec`'s half is the compiler's now as well —
`items` is `hidden`, so `.items` outside `vec.npk` is `NITPICK-TYPE-080`, and
`count`/`cap` are `sealed` (read them; never write them) — `SAFETY.md` S-23 and
S-24a. `Bytes`' half stays this library's: a sealed `buf` still admits a write
THROUGH `b.buf.ptr`.)*
*(2026-09-25, cycle 0.0.4d: `Bytes`' half is the compiler's too — `buf` is `hidden`
(RX-163), so `b.buf` outside `bytes.npk` is `NITPICK-TYPE-080`, and the capacity is
`bytes_capacity(@b)`. The tree check stays for the owning files.)*

**An `Optional` is not `pick`-able.** `pick (m) { (NIL) {…}, … }` is
`NITPICK-PARSE-005`. Test `== NIL`, read with `??` (`API.md` A-2a).

**A generic body is checked at EVERY instantiation** (D-264), so a generic
operation that **copies** its element cannot exist at any `T` —
`vec_fill<T>` is `NITPICK-TYPE-046` and `move` does not rescue it. If you want a
filled arena, `vec_init_zeroed` over `calloc` is the shape that works.

**Bind owning intermediates.** `f(g(x))` **leaks** when `g`'s result owns
memory — an unbound temporary is never dropped (the compiler's D-183 debt).
`string_concat`, `string_slice`, interpolation, a `buffer`, an owning struct.
It does *not* apply to `string_bytes`, a range view, or any scalar. Write
`Bytes:b = …; f(b);`.

**Exit status is one byte.** `exit 321` reports 65, silently. Compose weights
that cannot sum past 255, or print the value and assert on stdout.

**`npkc`'s exit codes are an alphabet and `2` is not a refusal.** `0` success;
`1` refused **with diagnostics**; `2` the driver could not proceed and judged
nothing, **with an empty stderr**; `3` a trap. A test expecting 1 that gets 2
was never compiled. And a **missing import** exits `1` with
`NITPICK-RESOLVE-005` — the very code a rejection fixture expects — so a
rejection test with a typo'd path passes for the wrong reason. Only B-7's
code-set equality tells them apart.

**A file's `mod:` name must equal its basename**, and no identifier may begin
with a digit. Adjacent string literals do not concatenate; `discard(x);` takes
parentheses; `defer { … }` takes no trailing semicolon; declarations end `};`
and control-flow blocks do not.

**`npkc` writes its emission to STDOUT.** Redirect it, or ~50 000 bytes of IR
land in your transcript. And capture an exit status with `; echo "exit=$?"`
**immediately** after the command and **never through a pipeline** — `$?` after
a pipeline is the last filter's status, and this ecosystem has paid for that bug
four times, each time by someone who had just read the warning.

## 7. What this subcycle must NOT do

- **Do not parse a construct.** Alternation, groups and quantifiers are 0.1.1.
  A skeleton that half-parses is a skeleton whose shape was chosen by the first
  construct that fitted it.
- **Do not resolve a class.** `\w` and `\p{L}` are parsed to *unresolved* items
  at 0.1.3 and resolved at 0.3. A parser that needed the Unicode tables would
  make cycle 0.1 depend on cycle 0.3 and neither would be testable alone.
- **Do not use native recursion**, even "just for now". 0.1.2's whole gate is
  that 10 000 levels is a clean refusal rather than a segfault, and the language
  has no stack guard. The temptation is exactly how the hazard survives to 1.0.
- **Do not add a second `error:` identity.** One, `ERegexPattern`, and
  `check_error_budget` fails the run if that changes. A second is a major
  version, because REACH-002 makes it a source break in every consumer.
