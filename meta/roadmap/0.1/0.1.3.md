### 1.2 O-Y2's premise is false, and the engines disagree

O-Y2: *"whether `x` mode ignores whitespace inside classes. Rust does not; Perl does with `xx`. Recommendation: do
not, matching Rust, and refuse `xx`."* `COMPAT.md` §2 carries the same claim as a row. Per the digest, and run here:

| engine, version | `(?x)[a b]` | `(?x)[a#b]` | source |
|---|---|---|---|
| Rust `regex` 1.13.1 (regex-syntax 0.8.11) | `a` or `b` — the space ignored | unclosed — `#` begins a comment inside the class | docs.rs: *"whitespace is ignored everywhere, including within character classes"*; built and run here |
| Java 21 (SE 27's documentation) | the space ignored | unclosed | run here; *"Comments mode ignores whitespace within a character class"* |
| Perl 5.38 (5.44's `perlre`) | the space a member; with `xx`, not | `#` a member | run here; `/xx` since v5.26 drops a space or a tab only |
| Python 3.12 (3.14's documentation) | the space a member | `#` a member | run here |
| .NET 10.0.12 | the space a member | `#` a member | run here; *"White space within a character class is always interpreted literally"* |
| PCRE2 10.49 | a member; `xx` drops a space or a tab | a member | its documentation |

So the recommendation's reading would have read every spaced `(?x)` class from Rust or Java otherwise than they do,
with no word said; Rust's reading would do the same to Perl's, Python's and .NET's. And Rust refuses `(?xx)` as a
repeated flag. PD-45.

### 1.3 Y-17's precedence is no engine's

Y-17 ranks union, then `--`, then `~~`, then `&&`. Rust's documentation: ranges, then union, then *"intersection,
difference, symmetric difference. All three have equivalent precedence, and are evaluated in left-to-right order"*,
then negation. UTS #18 revision 25: *"This specification does not require any particular operator precedence
scheme"*; its own syntax binds every operator at one level; *"precedence may put all operators on the same level, or
may take union as binding more closely"*. Measured in Rust: `[a&&a~~b]` is `a` or `b` (Y-17's order: `a`), and
`[ab~~b--a]` matches nothing (Y-17's: `a`). A mix of `&&` and `--` alone reads the same either way; `~~` after `&&`,
or `--` after `~~`, does not. PD-40.

### 1.4 What the class shapes mean elsewhere, where §1 and §5 do not say

`SYNTAX.md` §1 lists what a class may hold and leaves `ClassAtom` undefined; nothing says how `]`, `-` or a doubled
`&`, `-`, `~` is read where it could be two things. Measured in the four engines run here:

| shape | Rust | Perl, Python | this plan (PD-41) |
|---|---|---|---|
| `[]a]`, `[^]a]` | `]` first is a member | the same | the same |
| `[]`, `[^]` | unclosed | unclosed | `UnclosedClass`, its sentence saying the `]` was a member |
| `[-a]`, `[a-]`, `[a-c-e]` | `-` a member | the same | the same |
| `[]-a]` | `]`, `-`, `a` | the range `]`–`a` | Rust's reading |
| `[--a]` | `-`, `a` | the range `-`–`a` | refused: an operator with nothing before it |
| `[!--]` | `!` (`--` with an empty side) | the range `!`–`-` | refused: an operator with nothing after it |
| `[a&&]`, `[&&a]`, `[a&&&&b]` | the empty set on the empty side | no operators: `&` and `a` | refused, `ClassOpMismatch` |
| `[\w-.]`, `[a-\d]` | refused | Perl: members; Python: refused | refused, `BadClassRange` |
| `[[a]-z]`, `[[:alpha:]-z]` | members | no nested classes: `[[a]` is a class, `-z]` three bytes after it | refused, `BadClassRange` |
| `[!-[]` | the range `!`–`[` | the same | refused, `BadClassRange`: a `[` inside a class always opens one |
| `[[:alpah:]]`, `[[:alpha]]` | a nested class of its bytes | Perl: the first refused, the second a class and a `]`; Python: each a class and a `]` | refused, `UnknownPosixClass` |
| `[a[b]]` | a nested class | the class `[`, `a`, `b`, then a `]` | Rust's reading |

Where Rust reads a likely mistake in silence, or the engines read a shape two ways, the plan refuses it with a
sentence saying what to write; everywhere else it reads the shape as Rust does. No pattern the parser accepts is read
otherwise than Rust reads it — §1.9's cross-check.

### 1.5 A class read by a `while` of its own, on an explicit stack of its own

A class never contains a group, so the parser reads it in `parse_class`, a `while` the walk's `while` calls at a `[`
and which returns at the class's `]`. A nested `[` saves the class being read on `Parser.classes`, a
`Vec<ClassFrame>`, and its `]` takes it back — `p.stack`'s shape for groups, one level down. The operators fold left:
a frame holds the union being read and everything before the last operator as one node — the first union, then a
`ClassOp` of that and the next union — so a class's tree is a left-leaning chain, Y-27's `ClassOp` with `a` the left
operand and `b` the right, each union a `Class` of its own. The cursor's one byte of lookahead serves throughout: an
operator's first byte is read and its second eaten, and `[:` is decided by the byte after the `[` — which is why a
`[:` that is no POSIX class is refused rather than re-read as a nested class (Rust's reading), since the cursor does
not go back (RX-173). `check_no_recursion` reads 110 functions after step 2, no cycle (block 2). PD-41.

### 1.6 The bound: one count, groups and classes together

0.1.2 bounded the groups and left the classes to this subcycle (Y-35's last sentence). One count: a `[` that would
open a class while groups and classes — 250 together — are open around it is `NestTooDeep` at that `[`, before a byte
after it is read; a `(` is checked as before, since no class is open where a `(` opens a group; a POSIX class's `[:`
opens no class. Two counts under one constant would let 250 groups hold 250 classes, 500 levels where 0.2's walks are
promised 250. The refusal's sentence is built from its four fields, none of which says whether the byte was a `(` or
a `[` (Y-34), so it names both, and 0.1.2's held sentence changes. A class's operators deepen its tree by one node
each, which the pattern's length bounds and this bound does not; S-19's walks hold their own stacks for it. Measured
after step 2: 250 nested classes parse; the 251st `[` is `NestTooDeep` at byte 250, and so is a `[` inside 250 groups,
and the 126th `[` inside 125; 10 000 nested classes and 65 536 bytes of `[` too, forty runs a leg (block 2). PD-42.

### 1.7 No pattern reaches `EmptyClass`

With `]` a member when it comes first — Rust, Perl and Python alike, measured — `[]` and `[^]` never close, and every
class the parser builds holds a member: `EmptyClass` is a kind no pattern provokes, the shape Y-25 forbids and RX-181
retired `EmptyAlternate` for. It is not retired here: a class that resolves to no codepoint, as `[a&&b]` does, is a
likely mistake only resolution can see, which is cycle 0.3.4's. Step 2 opens a new open question, the next O-Y
number, with that recommendation.

### 1.8 Outside a class, `\d` and `\p` were no subcycle's

Y-27 says a `PerlClass` is *"`\d` `\w` `\s`, in a class or out"*, but §1's `Atom` names neither it nor `UnicodeClass`,
and the cycle README gives 0.1.4 *"every escape in §1's `Escape` production"*, which holds neither. They are read by
the code the class parser holds, so this subcycle takes them, outside a class as in one. PD-43.

### 1.9 Every accepted shape against Rust, and every refused one

### 1.10 A POSIX class written as a whole class

`[:alpha:]` is a class of `:`, `a`, `h`, `l` and `p` in Rust — measured, as each of the thirty-one shapes below was —
and almost never what was meant. GNU `grep` 3.11 refuses it — *"character class syntax is [[:space:]], not [:space:]"* —
by the rule gnulib's `dfa.c` states: a bracket expression, negated or not, whose first and last members are `:`, with a
member between that is not, and no range, class or collating element in it. Run on the thirty-one (the digest lists
them), `grep` refuses sixteen and reads fifteen as their members, `[::]`, `[:::]`, `[:alpha]`, `[a:alpha:]`, `[:a-z:]`
and `[:[:alpha:]:]` among them. The plan refuses an outermost class whose every member is one codepoint written as
itself, the first and the last `:` and another not: `grep`'s rule, with this syntax's escapes, nested classes and
operators read as written. On the thirty-one, the parser after step 4 reads twenty-seven as `grep` does, and the four it
reads otherwise — `[:\:]`, `[:\d:]`, `[:foo\:]` and `[:a&&b:]` — each hold an escape or an operator, which `grep`'s
brackets do not have: a `\` is a member there. `[:foo\:]` is the refusal's own advice followed — *"Write `\:` to match a
`:`"* — so an escape at either end makes a class one written as a class. The refusal names the POSIX class when the name
is one of §5.1's. PD-44.

## 4. What will bite

- **The cursor has one byte of lookahead and no rewind.** An operator is its first byte read and its second eaten;
  `[:` is decided by the byte after the `[`. A later construct that needs more asks `cursor.npk` for it by a decision
  (RX-173) — which is why `[:` that is no POSIX class is refused rather than re-read.
- **`&&` must short-circuit**, and the parser leans on it: `((b == CH_AMP) || …) && (raw cursor_eat(@p.c, …))` eats a
  second byte only after the first is an operator's. The compiler's reference says it does; `parse_classes` case 3,
  `[aa]`, is the measurement — evaluated eagerly, the second `a` would be eaten (measured in a copy: exit 3).
- **A `-` the pattern ends on must not reach `class_range`**: the branch tests for `CURSOR_END`, and without it `a[b-`
  reads past the pattern and traps `OutOfBounds` (§1.11's `dash-at-end`). A later edit to that branch keeps the test.
- **`stack`, `end`, `range` and `in` are reserved**; the class code uses `cf`, `hi`, `upto` and `lo` (a `ClassRange`'s
  low end, as an `AstNode` local).
- **An exit status is one byte**, and the units' cases run to 90 and no higher, since each unit's `failsafe` arms exit
  91 and above; every assertion is through a value that is not vacant — `ClassRange` and `Class` are not `AstKind`'s
  first variant, `UnclosedClass` not `PatternErrorKind`'s, and an offset of 0 is asserted only beside a kind and a
  length.
- **`apply.py` stages what it applies.** Commit after each block and nothing else: `git status --short` first. A STOP
  writes nothing. A re-run on a later day STOPs where it would say ALREADY (the dates differ).
- **The mutants edit a copy**, `$A/ctl/mut_<name>`, removed after each; a mutant whose old text is not in `parse.npk`

## 6. For the orchestrator, the author and the compiler seat — found at planning
