Every command that produced a verdict in `meta/roadmap/0.0/0.0.0.md` §7, with
its exit code. This file is committed VERBATIM rather than summarised: a prose
summary of a run is not evidence of it, and a subcycle in a sibling repository
had its emission claims failed by its own verifier for exactly that.

Why all four steps, every time: `npkc` exiting 0 does not mean a program is
well-formed. A root file with `main` and no `failsafe` compiles at exit 0 and is
refused only by `llc`, a long way from the cause (the workbench registry's
O-N11, the compiler's DEF-5). A probe that was only compiled is a probe that has
not been run.

The four-step recipe (`0.0.0.md` §2), run for every probe below:

-- C1. probe 09 — where `comptime` folding stops -----------------------------

Nine `comptime func:` bodies, each adding one construct. The forcing form
`comptime(f(...))` in a value position is what must fold.

    plain constant                     exit 0   FOLDS
    mutable local + arithmetic         exit 0   FOLDS
    counted while loop                 exit 0   FOLDS
    string_byte_length                 exit 0   FOLDS
    string_is_empty                    exit 0   FOLDS
    string_equals                      exit 0   FOLDS
    string_concat                      exit 0   FOLDS
    string_bytes, then .len            exit 1   NITPICK-TYPE-004 tc.npk:4:15: `comptime` requires an expre
    string_bytes, then an INDEX        exit 1   NITPICK-TYPE-004 tc.npk:4:15: `comptime` requires an expre

    The wall is `string_bytes`, and `.len` alone is already past it: the index
    never gets a chance because the view is never produced. The four builtins
    that fold are exactly the four `fold_string_builtin` handles.

-- C2. probe 11 — the bitwise operators --------------------------------------

    a >>> b                  exit 1   NITPICK-PARSE-002 top.npk:5:19: expected an expressi
    a >> b                   exit 0
    a & b                    exit 0
    a | b                    exit 0
    a ^ b                    exit 0
    ~a                       exit 0

    `>>>` is in TYPE_REFERENCE.md's operator table and not in the lexer. It
    costs nothing, because `>>` on an unsigned type is already logical:

    $ npkc tshift.npk   # (1u64 << 63u64) >> 63u64 -- exit 1 logical, 2 arithmetic
      exit 0   (npkc)
      exit 0   (llc)
      exit 0   (ld.lld)
      exit 1   (run)  -- 1 = LOGICAL. `>>>` would be a synonym.

    And the literal that cannot be spelled, which is why `~0u64` is used above:
    $ npkc tlit.npk   # uint64:x = 18446744073709551615u64;
      NITPICK-LEX-004 tlit.npk:3:16: this literal is outside the 64-bit literal envelope (D-148); a type's outermost values are constructed arithmetically, not spelled
      exit 1
