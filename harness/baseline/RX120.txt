THE RX-120 EXPIRY, REPRODUCED.  cycle 0.0.5, 2026-09-06.

WHY THIS FILE EXISTS. RX-120 is this repository's most travelled finding: the
undefined-symbol difference cannot see a syscall, therefore `check_no_syscalls`
needs a second layer that scans the IR's call edges. It was measured at compiler
`950bb1d` and it was correct there. IT IS NO LONGER CORRECT AT `3d15ac9`, and
until this file existed that reversal was recorded in three places as an
ASSERTION -- `harness/build.py`, `meta/DECISIONS.md` RX-131, and `0.0.4.md` --
with no transcript behind any of them, unlike the original measurement, which
`0.0.2.md` did back with a table.

That gap mattered more than usual because the finding is PIN-DEPENDENT and was
being carried to four sibling repositories as current fact. A claim that four
repositories are about to act on should be reproducible by running a file, not
by trusting a sentence.

WHAT IS SHOWN, AND IT IS BOTH PINS RATHER THAN ONE. Sections A-C measure the
floor and a syscaller at the working pin. Section D re-runs the identical two
commands under the SUPERSEDED compiler, which this workbench still keeps -- so
the expiry is demonstrated inside one transcript instead of being an argument
between two dated claims. Section E says what did not expire.

READ THE EXIT CODES. Every command is followed by `exit=$?` on its own line
with no pipeline between, because `$?` after a pipeline is the last filter's
status and this ecosystem has shipped a whole sweep on that bug.

ONE SUBSTITUTION, DECLARED BECAUSE A TRANSCRIPT THAT CLAIMS TO BE VERBATIM MUST
SAY WHERE IT WAS TOUCHED. The two `npkc` paths below were absolute when the
commands ran; the workbench root is rewritten to `$TOOLCHAIN` so no absolute
path is committed. Nothing else is edited, and the two sha256 lines are the
identities that actually matter -- they pin which binaries produced these
numbers regardless of where anyone keeps them.

    $TOOLCHAIN = <workbench>/.internal/toolchain

-------------------------------------------------------------------------------

## E. WHY RX-120'S REMEDY IS NOT RETIRED BY ANY OF THE ABOVE.
##
## The symbol layer now sees THAT a syscall exists. It does not say WHERE.
## The IR call-edge scan does, and it is unaffected by what the prelude
## chooses to emit -- so it survives the next prelude change too.
$ python3 -c "import harness.irscan as s; print(s.kernel_call_edges(open('.internal/rx120/sys.ll').read()))"
irscan public names: ['DENIED', 'edges', 'normalise', 're', 'scan']
exit=0

THE READING.

  compiler    floor   syscaller   difference          RX-120's claim
  950bb1d     29      29          EMPTY               TRUE
  3d15ac9      2       3          {npk_sys6}          FALSE

The mechanism is the compiler's D-262 (its 1.5.2d): a prelude item is emitted
only when it is referenced. `npk_sys6` was in every translation unit and is now
in the ones that use it, so the symbol that could never be a difference is now
exactly the difference.

WHAT DOES NOT EXPIRE, and it is why RX-120's DECISION stands while one of its
CLAUSES does not. The symbol layer answers "does this object need a kernel
symbol". The call-edge layer answers "which function calls it". The second
question is the one a reviewer needs, no symbol set has ever been able to
answer it, and the answer does not depend on what the prelude emits -- so a
future prelude carrying `npk_sys6` again would blind the first layer and leave
this one exactly as strong. Rule B-2a keeps both.

AND THE GENERAL LESSON, which is the part a sibling repository should take:
A MEASUREMENT AGAINST A MOVING COMPILER IS DATED BY ITS COMMIT OR IT IS NOT
DATED. Three sites in this tree said "measured at the pin". "The pin" is a
name that re-points, so those sentences became false while nobody edited them
and no check could see it -- there is nothing lexically wrong with a true
sentence about a different compiler. Name the commit.
